# ResearchClaw M0–M2 项目开发计划与进度

> 范围：M0（后端引擎 / 证据闭环）→ M1（实时通道 + 三栏面板）→ M2（ClaudeCodeAdapter workflow 模式）
> 目标：在 WJ 的 V2/V3 架构约束下，完成从「纯 mock 科研状态机」到「可真实调用 Claude Code、带 SSE 实时面板、有成本护栏」的端到端研究控制台。
> 状态：✅ M0-M2 已验收并修复关键缺口（详见 §8 进度更新）
> 最后更新：2026-06-11

## 0. 结论先行

M0–M2 的核心交付物是：

1. **M0**：一个可约束、可回退、证据闭环的研究工作流引擎。
2. **M1**：一个用真实后端数据驱动的 React + TypeScript 三栏研究控制台。
3. **M2**：让 `contract_draft` 可由真实 Claude Code(Haiku, headless) 产出，并实时进面板。

本计划把 WJ 已撰写的技术路线、进度交接、红线整理成可执行的开发任务表，每项都带验收标准、依赖关系和风险提示。开发前请确认本计划；确认后我会按里程碑逐项推进，并在此文档中实时更新进度。

## 2. 架构红线（WJ 要求，必须遵守）

| 红线 | 含义 | 检查点 |
|------|------|--------|
| **Engine 是唯一科研状态源** | 只有 `ResearchOrchestrator` 能写 research state；adapter/workflow/gateway 都不能直接改 phase/phase_history | 每次提交前跑 `npm test` |
| **两通道物理分离** | 结论只来自「结构化 artifact → gate」；transcript/raw_log/cli_chunk 只代表过程透明度，永不当结论 | 面板右栏明确标「过程」 |
| **Artifact + gate 才推进 phase** | 每个 phase transition 必须有 gate 结果；mock 下也要过 gate | gate 测试全覆盖 |
| **Consult 是旁路** | consult 不推进 research state，不进 claim evidence | M2 仍 disabled |
| **默认 Haiku，绝不默认 Opus** | 真实 CLI 默认 `claude-haiku-4-5`；非 Haiku 必须显式配置并告警 | `server.js` 启动时检查 |
| **Mock 永远是回放底座** | CI / `demo:fixture` 全 mock零额度；真实 CLI 仅在显式开关开启 | 不配置时 `RESEARCHCLAW_ENABLE_CLAUDE` 为 falsy |
| **API key 不泄露** | key 不进日志/SSE/artifact/错误信息/前端状态 | provider status 脱敏 |
| **降级要诚实** | 回退 mock 后产物 `adapter:"mock"`，面板如实显示 | 来源徽章 + 降级 banner |

## 8. 本次审计与修复记录

### 8.1 已修复：M2-01 `contract_draft` 阻塞后无法 recover

**问题**：`contract_draft` 阶段进入 `blocked` 后，`state.block.retreat_to` 为 `null`，`POST /recover` 报 "No retreat target is available"。

**修复内容**：
1. `researchclaw/engine/orchestrator.js`
   - `retreatTargets` 增加 `contract_draft: "contract_draft"`
   - `_failContractRun` 使用 `retreatTargets.contract_draft` 代替硬编码 `null`
   - `recover()` 对 `contract_draft` 目标特殊处理：设置 `pendingRun`、返回 `needs_draft: true`、显示 `phase_running`
2. `researchclaw/server.js`
   - `/recover` 端点在 `result.needs_draft` 时后台调度 `executeContractRun`
3. 新增回归测试
