# ResearchClaw V3 总验收矩阵

> 版本：V3 验收矩阵
> 目标：为 V3-M0 到 V3-M6 提供统一验收口径

---

## 0. V3 总目标

第三版完成后，ResearchClaw 应成为：

```text
一个以 Research Workflow Engine 为唯一状态源、可按 phase 选择 Claude Code/Gemini CLI/Codex CLI、能在 idea_review 后运行实验验证并把结果回灌证据链的科研工作流编排器。
```

不是：

- 只调用 Claude 的单模型工具。
- 用 Claude Code 加载 Gemini/Codex 的统一模型壳。
- 多 provider 随意填 key 的聊天平台。
- experiment 旁路系统。
- 不经过实验验证就宣称 idea 成功的总结器。

## 3. 必跑测试建议

### 3.1 每阶段基础测试

```bash
cd researchclaw
npm test
npm run demo:fixture

cd researchclaw/web
npm run test
npm run typecheck
npm run build
```

### 3.2 真实 CLI 冒烟

只在本地验收或交接时跑：

```bash
cd researchclaw
npm run smoke:claude
```

后续可新增：

```bash
npm run smoke:gemini
npm run smoke:codex
npm run smoke:v3-experiment
```

真实 smoke 要记录：

- 使用 provider/CLI/model。
- 是否走 `API.md` ResearchClaw 专用配置。
- 是否生成 artifact。
- 是否泄露 key。
- cost/cache/budget 摘要。

## 4. 安全与边界验收

| 红线 | 验收方式 |
| --- | --- |
| engine 是唯一科研状态源 | adapter/workflow 不直接写 state |
| transcript/raw_log 不代表结论 | UI 与 artifact 类型明确标注 |
| artifact + gate 才推进 phase | 每个 phase transition 有 gate 测试 |
| consult 是旁路 | consult 不改 phase_history，不进 claim evidence |
| mock 是回放底座 | CI 默认 mock，全测试零额度 |
| API key 不泄露 | 响应、日志、SSE、artifact、错误路径有测试 |
| experiment 非旁路 | 实验 phase 在 orchestrator 中推进 |
| summary 消费实验 | summary gate 检查 experiment_review |

## 6. 最终验收话术

```text
V3 在 V2 的可约束科研链路上完成了三件事：
第一，ResearchClaw 能按研究阶段选择 Claude Code、Gemini CLI、Codex CLI 或 mock；
第二，三套 CLI 的过程流、artifact、成本与来源都能被追踪；
第三，idea_review 后加入实验验证，summary 必须基于 experiment_run/review 的证据诚实表述结论。
```
