# ResearchClaw V3-M0 基线核查与交接

> 阶段：V3-M0
> 目标：冻结 V3 起点，确认第二版能力边界与当前代码一致
> 前置：第二版 M0-M4 已完成，第三版总纲见 `第三版技术路线指南.md`

---

## 0. 一句话目标

```text
在进入 V3 开发前，先把 V2 当前能力、测试基线、真实 CLI 冒烟状态、Settings 占位状态全部核清，形成后续 M1-M6 的稳定起点。
```

V3-M0 不做新功能，只做核查、记录、风险冻结。

---

## 1. 范围

### 1.1 必须做

- 跑通后端测试，记录通过数量。
- 跑通前端测试、typecheck、build，记录通过数量。
- 跑通 `demo:fixture`，确认 mock 回放仍稳定。
- 可选跑 `npm run smoke:claude`，记录真实 Claude Code 链路证据。
- 核查当前 adapter 能力：ClaudeCodeAdapter + mock 已有，Gemini/Codex adapter 未实现。
- 核查 Settings 状态：Settings UI 已有，但模型配置仍主要是前端本地壳。
- 核查 V3 总纲与代码差距，输出交接记录。

### 1.2 明确不做

- 不新增 Gemini/Codex adapter。
- 不新增 phase CLI policy。
- 不改 phase 顺序。
- 不插入实验 workflow。
- 不重构前端 Settings。

## 3. 建议核查命令

在 `researchclaw/` 下：

```bash
npm test
npm run demo:fixture
```

在 `researchclaw/web/` 下：

```bash
npm run test
npm run typecheck
npm run build
```

真实 Claude 冒烟，可选执行：

```bash
npm run smoke:claude
```

注意：`smoke:claude` 会真实消耗 Haiku 额度，只在本地验收时跑，不进 CI。

---

## 4. 验收标准

- 后端测试、前端测试、typecheck、build 结果被记录。
- mock fixture 能跑完，不依赖真实 API。
- 明确 V3 不补做 V2 M3/M4，它们已完成。
- 明确 Gemini/Codex 只有 provider 配置解析，CLI adapter 未建。
- 明确 Settings 模型管理仍未后端化。
- 输出一份可作为 V3 起点的交接记录。

---

## 5. 红线

1. 不为核查而修改业务逻辑。
2. 不把 smoke 失败误写成 V2 功能缺失，先区分本机 CLI/API 环境问题。
3. 不提交 `API.md` 或任何 API key。
4. 不用真实 CLI 替代 mock CI。
5. 不改 `第三版技术路线指南.md` 的架构判断，除非发现与代码事实冲突。

---
