# M2 技术路线（ClaudeCodeAdapter workflow 模式）— 后端交接文档

本文档给**接手 M2 后端**的开发者。读完应能独立实现真实 Claude Code 接入、沙箱、成本护栏与降级，而不需回头问架构。前端侧改动见同目录《M2技术路线-前端.md》。

前置：M0（引擎/gate/证据闭环）+ M1（实时通道 + 三栏面板 + 证据映射 / artifact 详情）已完成并测试通过（后端 `node --test "tests/*.test.js"` 53/53）。

---

## 0. 一句话目标

```text
让至少一个 phase（M2 定为 contract_draft）由真实 Claude Code(Haiku, headless) 产出，
产物经「写文件 + 读文件 + 既有 gate」强制校验，非法输出被拦不入库；
CLI 过程经事件总线实时进面板；默认 Haiku、有 token/turn/超时/会话预算护栏；
无 key / 超限 / 失败时优雅降级 mock，流程不中断。mock 永远是回放底座。
```

对齐《第二版技术路线指南》§8 M2 验收：**contract_draft 由真实 Haiku 产出并过 gate；非法输出被拦；超限/无 key 降级 mock。**

## 1. 范围

### 1.1 M2 必须做（后端）
- `adapters/claudeCode.js`：`ClaudeCodeAdapter`，实现既有 `ModelAdapter` 接口（§3），**workflow 模式**（结构化产物）。
- `sandbox/`：每次 CLI 运行的独立工作目录管理与清理，受限 `--allowedTools`。
- 成本护栏：默认 `claude-haiku-4-5`；单次 `--max-turns` / 超时 / token 上限；会话级累计预算；超限中止并标记 fail。
- 降级：无 API key / 找不到 `claude` 可执行 / 超时 / 超预算 / 非法输出 → 回退 mock（或回退到可重跑 phase），**绝不崩**。
- stream-json 解析 → 经 `EventBus` 实时推 `cli_chunk`；运行结束抽一条结构化摘要 `raw_log`。
- 用量统计：把每次 CLI 用量累计进 `state.usage`（供面板与 M4 成本告警）。
- 按 phase opt-in 的适配器路由（§7）：M2 仅 contract_draft 走 Claude，其余仍 mock。
- 配置开关（§8）：env / 注入式，默认全 mock，显式开启才接真实 CLI。

### 1.2 M2 明确不做（留 M3/M4）
- **consult 一问一答**（人机对话、`--resume` 多轮、promote-to-artifact）→ M3。
- 其余 phase（literature/baseline/idea/review/summary）接真实 CLI → 不在 M2 强制范围（接口已通用，按需 opt-in，但 M2 只验 contract_draft）。
- **完整指标面板 + 成本告警 UI** → M4（后端 M2 只负责把 `usage` 算准、存好）。
- 不接 Gemini / Codex；不引数据库。

## 2. 架构变化与新增模块

```text
ResearchOrchestrator（唯一状态源，不变）
  └─ this.adapter.run(request)              ← 接口签名不变（§3）
       └─ routeAdapter（§7，按 phase 选择 + 降级）
            ├─ ClaudeCodeAdapter            ← 新增（adapters/claudeCode.js）
            │    ├─ buildPrompt(request)
            │    ├─ sandbox.create()         ← 新增（sandbox/index.js）
            │    ├─ spawn claude (stream-json)
            │    │    └─ 每个事件 → eventBus.emit(projectId, {type:"cli_chunk",...})
            │    ├─ 读 sandbox/out.json
            │    ├─ validateSchema(out, request.output_schema)  ← schema 注册表（§4.2）
            │    ├─ costTracker.record(usage)  ← 新增（engine/cost.js）
            │    └─ sandbox.cleanup()
            └─ MockModelAdapter（回放底座，不变）
```

新增文件：
- `adapters/claudeCode.js` — `ClaudeCodeAdapter`。
- `adapters/route.js` — `createRoutingAdapter({ phases, primary, fallback })`（按 phase opt-in + 降级）。
- `sandbox/index.js` — `createSandbox()` / `cleanupSandbox()`。
- `engine/cost.js` — `CostTracker`（会话累计 + 预算判定）+ Haiku 计价常量。
- `adapters/schemas.js` — `output_schema` 名 → 校验器映射（forced schema 落地）。

不动：`engine/orchestrator.js` 状态机主体、`workflows/*`（adapter 接口不变，零改动）、所有 M0/M1 gate。

## 3. ModelAdapter 接口（不变，照抄实现）

所有 adapter 实现同一个 `run`。**ClaudeCodeAdapter 必须严格匹配，workflow 层才能零改动。**

```js
// 入参 request（来自 workflows/*，如 contractDraft.js）
{
  task_id: "contract_draft",
  project_id: "proj_xxx",
  phase: "contract_draft",
  instructions: "Draft a machine-checkable research contract.",
  inputs: [ { ref, type, content }, ... ],   // type 如 research_direction / research_contract / revision_feedback
  output_schema: "ResearchContractV1"          // 字符串名，M2 用它选 JSON schema
}

// 成功返回
{ ok: true, adapter: "claude", output: <结构化对象>, raw_ref?: <transcript 文件 ref>, usage?: <见 §4.5> }

// 失败返回（参照 adapters/types.js 的 adapterError）
{ ok: false, adapter: "claude", error: { code, message, retryable } }
```

> 关键：`output` 必须是**已解析的结构化对象**（不是自然语言）。workflow 拿到后用 `createArtifact` 落档，再由 orchestrator 的既有 gate 校验。ClaudeCodeAdapter 的 `output` 来自**读 sandbox/out.json**，不是解析 stdout 文本（红线 §2.1）。

## 4. ClaudeCodeAdapter 设计

### 4.1 workflow 模式 CLI 调用

```bash
claude -p "<buildPrompt(request)>" \
  --model claude-haiku-4-5 \
  --output-format stream-json \
  --allowedTools "Read,Write,WebSearch" \
  --max-turns 20 \
  --cwd <sandboxDir>
```

`buildPrompt(request)` 拼装：
1. `instructions`（任务）。
2. `inputs` 序列化（research_direction / 上一版 contract / 修订反馈等，按 type 标注）。
3. **强约束尾句**：要求把唯一结果写入 `./out.json`，严格符合给定 schema（把 §4.2 的 JSON schema 文本附上），不要输出多余文件，不要在对话里给结论。

用 `node:child_process` 的 `spawn`（非 `exec`，要流式读 stdout）。`--cwd` 指向沙箱目录（§5）。

### 4.2 forced schema（写文件 + 读文件 + gate）

`adapters/schemas.js` 维护 `output_schema` 名 → `{ jsonSchema, validate }`：

| output_schema | 对应 | 校验器（已存在，复用） |
| --- | --- | --- |
| `ResearchContractV1` | 研究契约 | `contract/schema.js` 的 `validateResearchContract` |
| `DemoSummary` | 总结 | （M2 不接，留通用接口） |
| 其余（literature/baseline/...） | 各 phase | 既有 gate（M2 不接，预留） |

流程（adapter 内）：
1. spawn 跑完 → 读 `<sandboxDir>/out.json`；读不到 / 非 JSON → `adapterError("missing_output", ..., retryable=true)`。
2. `validate(out)`：**先做 schema 级**校验（字段齐全/类型）；不过 → `adapterError("schema_violation", errors, retryable=true)`，**绝不返回 ok**。
3. 过 → `{ ok:true, output: out, ... }`。
4. orchestrator 收到 artifact 后，**既有 contractGate 仍会再校一遍**（双保险）——这层不变。

> 「非法输出被拦」由 step 2（adapter schema 校验）+ 既有 gate 共同保证；任一不过都不会 commit，走 §6 降级/回退。

### 4.3 stream-json 解析 → 实时事件

逐行读 stdout（stream-json 每行一个 JSON 事件）。对每个事件：
- 提取 `{ type, subtype, text/tool, usage? }`，经 `eventBus.emit(projectId, { type: "cli_chunk", data: {...} })` 实时推面板（projectId 来自 `request.project_id`；adapter 在构造时注入 `eventBus`）。
- 累计 `usage`（input/output tokens）。
- **不把整段 stream-json 全文当结论**——它只进 transcript / 过程流（红线 §2.1）。

容错：单行解析失败跳过不崩；进程 stderr 收集进错误信息。

### 4.4 raw_log / 产物落档

- **transcript**：把整段 stream-json 原文写文件（sandbox 或 logs/），adapter 返回其 `raw_ref`。
- 运行结束抽一条**结构化摘要** `{ model, time, role, summary, artifact_refs }`（§指南 5.3「重要内容如何提取」），由 orchestrator 落成 `raw_log` artifact（复用现有 `recordRawLogArtifact` 思路，扩展 content）。摘要项本身是 raw_log，不是结论。
- 结构化 `output` 走 workflow 的 `createArtifact`（已有）→ `producer.adapter = "claude"`。

### 4.5 usage / 成本

adapter 汇总 `usage = { input_tokens, output_tokens, model, est_cost_usd, turns, duration_ms }`（cost 由 `engine/cost.js` 的 Haiku 计价算）。orchestrator 把每次调用累计进 `state.usage`：

```js
state.usage = {
  input_tokens, output_tokens, est_cost_usd,
  cli_calls, cli_failures, by_phase: { contract_draft: {...} }
}
```

> `state.usage` 是**后端新增字段**（先在后端加 + 补测试，engine 仍唯一源）。它随既有 SSE `snapshot` 一起到前端，无需新端点。M4 的成本告警建在它之上。

## 5. 沙箱（sandbox/）

- `createSandbox(projectId)`：建独立目录（建议 `os.tmpdir()` 下 `researchclaw-sbx-<runId>`，或 `.researchclaw/projects/<id>/sandbox/<runId>`），返回 `{ dir, cleanup }`。
- 传 `--cwd <dir>`，`--allowedTools "Read,Write,WebSearch"`（**默认不开 Bash / 删除等危险工具**，指南 §7）。
- 运行结束（无论成败）`cleanup()` 删目录；保留 transcript 时先把它复制到 `logs/` 再清沙箱。
- evidence store 落档前沿用 `util.js` 的 `redactSecrets`，**不写 API key / 完整敏感环境变量 / 未白名单 tool input**（指南 §7）。

## 6. 成本与安全护栏（硬性）

| 护栏 | 实现 |
| --- | --- |
| 默认模型 | `claude-haiku-4-5`；用 Opus/Sonnet 必须显式配置，且日志/面板告警（指南 §7）。 |
| 单次 turn 上限 | `--max-turns`（默认 ≤ 20）。 |
| 单次超时 | spawn 上挂定时器，超时 `kill` 子进程 → `adapterError("timeout", ..., retryable=true)`（默认 ≤ 120s，可配）。 |
| 单次 token 上限 | 解析 usage，超阈中止标 fail。 |
| 会话级预算 | `CostTracker` 累计；超阈则**后续 CLI 调用暂停**，返回降级信号，提示人工确认。 |
| 无 key / 无 `claude` | 启动时探测（env `ANTHROPIC_API_KEY` + `which claude`）；缺失 → 该 phase 直接走 mock。 |
| 降级不崩 | 任一失败码（missing_output / schema_violation / timeout / over_budget / spawn_error）→ 由 routeAdapter（§7）决定：回退 mock 或回退到可重跑 phase。 |

## 7. 适配器路由与降级（adapters/route.js）

保持 orchestrator/workflow 零改动：注入一个**组合 adapter**。

```js
createRoutingAdapter({
  phases: ["contract_draft"],   // 仅这些 phase 尝试 Claude；其余直接 mock
  primary: claudeAdapter,
  fallback: mockAdapter,
  costTracker
})
```

`run(request)` 逻辑：
1. `request.phase` 不在 `phases` 或 Claude 不可用（无 key）或 `costTracker.overBudget()` → 直接 `fallback.run(request)`，并标 `degraded:true`。
2. 否则 `primary.run(request)`；若 `!ok`（含 timeout/schema_violation）→ `fallback.run(request)`，标 `degraded` + 记一次 `cli_failures`，并 emit 一条 `cli_chunk`/事件让面板显示「已降级 mock」。
3. 返回结果带 `adapter`（"claude" 或降级后的 "mock"）——前端据此显示来源徽章（前端文档 §3）。

> 降级后产物的 `producer.adapter = "mock"`，面板必须诚实显示是 mock 产出（红线：两通道 + 不假装已接入）。

## 11. 测试要求（CI 不真调 CLI）

- **ClaudeCodeAdapter 用 stub 子进程 / 录制 fixture 测**：把一段真实 stream-json 输出录成 fixture（`fixtures/cli/contract-draft.stream.jsonl` + 对应 `out.json`），测试用一个假的 spawn（注入 `spawnImpl`）回放它，断言：解析出 usage、读出 out.json、schema 通过/拦截。
- **降级矩阵**：无 key / `claude` 不存在 / 超时（stub 不写 out.json）/ schema_violation（stub 写非法 out.json）/ over_budget → 都回退 mock，`ok:true` 且 `adapter:"mock"`，进程不抛。
- **成本**：CostTracker 累计、预算阈值触发暂停。
- **沙箱**：运行后目录被清理；落档经 redactSecrets。
- **SSE 事件序列**：cli_chunk 按行到达。
- 沿用 M0/M1 全部测试保持全绿；CI 默认全 mock、零额度（指南 §9）。真实 Claude 调用仅本地 / 显式开关。

## 12. 验收标准（对齐指南 §6.1）

- **V1 真实链路**：contract_draft 由真实 Claude(Haiku) 产出，过 contract gate，可 human approve。

- **V9 mock 回放仍稳**：不开 CLI 时 `node --test "tests/*.test.js"` 与 `demo-fixture` 全绿。

## 13. 红线（务必遵守）

1. **两通道物理分离**：结论只来自 `out.json` → schema → gate 的结构化 artifact；stream-json transcript 一律 `raw_log`，永不当结论（指南 §2.1）。
2. **engine 边界不破**：adapter 不改 research state；workflow 不绕过 contract；engine 不直接调模型（只经 adapter）。`ModelAdapter` 接口签名不变。
3. **默认 Haiku，绝不默认 Opus**；调试不烧钱是硬约束。
4. **mock 永远是回放底座**：真实 CLI 按 phase opt-in，不替换 mock；CI 零额度。
5. **沙箱 + 受限 allowedTools**，默认不放危险工具；落档 redactSecrets，不写密钥。
6. **降级要诚实**：回退 mock 后产物 `adapter:"mock"`，面板如实显示，不假装 Claude 跑了。
