# M3 技术路线（consult 一问一答）— 前端交接文档

本文档给**接手 M3 前端**的开发者。M3 前端就一件事：**把右栏从「只读过程流」升级为「可与 Claude 一问一答」**——点 Claude → 输入框解锁 → 发消息 → 流式回显 → 整轮入过程流，可「提升为 artifact」。后端侧见同目录《M3技术路线-后端.md》。

前置：M1（三栏面板 / SSE 实时 / artifact 抽屉）+ M2（右栏 `RightColumn` 升级、`ProcessFeedItem` 摘要卡片、`LiveChunks` 实时区、`AdapterBadge` 来源徽章、`useProjectStream` 处理 `cli_chunk`、`MetricsRow` 轻量 usage）已完成（web vitest 84/84、typecheck 绿）。

> M2 已经在 `RightColumn.tsx` 给 consult 留了**禁用占位**：模型按钮 `Claude`（disabled）+ 底部 `disabled` 输入框「M3 开放与 Claude 一问一答」。M3 就是把这两处接活。

---

## 0. 一句话目标

```text
右栏 Claude 按钮可点 → 进入对该 CLI 的一问一答视图；输入框解锁；
发消息 → 后端异步跑一轮 → cli_chunk(kind:consult) 流式回显（先占位、再定稿）→
整轮作为 raw_log(consult) 卡片入过程流；每轮带「提升为 artifact」按钮；
promote 后该轮标「已采纳为 consult_note（未过 gate，非结论）」。
Claude 未接入 / 超预算时输入禁用并诚实提示，绝不伪造对话。
模型固定 Haiku（不给选）。Gemini / Codex 维持占位。
```

---

## 1. 范围

### 1.1 M3 前端必须做
- **consult 对话视图**：右栏点 `Claude` → 展开一问一答区（消息列表 + 输入框 + 发送）。消息列表 = 用户 Q + Claude A（流式）。
- **流式回显**：用户发出后乐观插入「我的消息」+ 一个「Claude 正在回复…」占位；订阅 `cli_chunk(kind:"consult")` 增量拼接回答；收到 `consult_message` 事件后用定稿轮替换占位。
- **整轮入过程流**：定稿后该轮即一条 consult `raw_log`，沿用 M2 `ProcessFeedItem` 卡片（来源徽章 claude / 可点开 transcript）。
- **promote 按钮**：每条 consult 轮卡片带「提升为 artifact」；点击 → `POST /consult/promote` → 该轮标「已采纳为 consult_note」。
- **consult_note 视觉区分**：promote 出来的 `consult_note` 在「关键产物」列表里**和 gate 过的 artifact 明确分开**（独立分组 / 专属徽章「采纳笔记·未过 gate」），不混入结论。
- **不可用诚实态**：Claude 未接入 / 超预算 → 输入框 disabled + 提示「Claude 未接入，一问一答不可用」（复用 M2 降级语义，但 consult **不显示 mock 回答**）。
- 模型固定 Haiku：对话区可显一个静态「Haiku」小标，不给下拉。

### 1.2 M3 前端明确不做（留 M4）
- **完整运行指标面板 + 成本告警 / 阈值高亮**：M4。M3 不动 `MetricsRow`（consult 的 token 已被后端计进 `state.usage`，M4 再细化展示）。
- consult 多会话线 / 切话题 tab；选模型下拉。
- Gemini / Codex 对话：维持占位禁用。

## 2. 依赖的后端新数据 / 事件（M3 后端提供）

| 来源 | 形状 | 用途 |
| --- | --- | --- |
| SSE `cli_chunk`（扩展 `kind`） | `{ kind:"consult", role:"对话", text?, ts }` | 流式拼接 Claude 回答；按 `kind` 与 workflow chunk 分流 |
| SSE `consult_message`（新增） | `{ raw_log_ref, question, answer_summary, session_id, ts }` | 一轮结束，占位替换为定稿轮 |
| `state.consult`（新增，随 snapshot） | `{ session_id, turn_count, last_turn_at, raw_log_refs[] }` | 渲染 consult 轮列表（按序）、会话状态 |
| `state.current.consult_note_refs`（新增） | `string[]` | 「采纳笔记」分组渲染 |
| consult `raw_log` content | `{ model, time, role:"对话", summary, question?, session_id?, transcript_ref }` | consult 轮卡片（复用 `readRawLogSummary`，防御式扩字段） |
| `consult_note` artifact | `type:"consult_note"`, producer.adapter=`"claude"`, content `{ source_raw_log_ref, question, answer_text, note }` | 采纳笔记详情 |
| `POST /consult` 返回 | `{ ok, running:true }` 或 `{ ok:false, error }` | 发送态 / 不可用诚实提示 |

> **不要在前端伪造任何字段**。后端没给就不显；前端只调 HTTP/SSE，不本地拼 state（红线，与 M1/M2 一致）。consult 的「结论性」永远是 false——前端任何地方不得把对话当中栏结论。

## 3. 逐组件改动（`researchclaw/web/src/`）

### 3.1 `api/types.ts`
- `CliChunk` 加可选 `kind?: "consult" | "workflow"`。
- 新增 `ConsultMessage`（SSE 事件）`{ raw_log_ref; question; answer_summary; session_id; ts }`。
- `ProjectState` 加可选 `consult?: { session_id: string | null; turn_count: number; last_turn_at?: string; raw_log_refs: string[] }`。
- `ProjectCurrent` 加可选 `consult_note_refs?: string[]`。
- `ArtifactType` 联合加 `"consult_note"`。
- `CliRawLogSummary` 加可选 `question?: string; session_id?: string`（防御式）。

### 3.2 `api/client.ts`（加两个 mutation）
- `sendConsult(projectId, message): Promise<{ ok; running?; error? }>` → `POST /projects/:id/consult`。
- `promoteConsult(projectId, rawLogRef, note?): Promise<{ ok; artifact_ref }>` → `POST /projects/:id/consult/promote`。
- 复用现有 `postJson`；`sendConsult` 对 `ok:false` 不抛成红错，而是把 `error` 透给 UI 作诚实提示（不可用是预期态，不是异常）。

### 3.3 `api/useConsult.ts`（新增小 hook，或并入 `useProjectStream`）
- 维护**本地 consult 视图态**：`turns: ConsultTurn[]`，其中流式中的最后一轮是「乐观态」。
- 输入：`cli_chunk(kind:"consult")`（增量文本）+ `consult_message`（定稿）+ `snapshot`（真相源：`state.consult.raw_log_refs` 决定已落定的轮）。
- 规则：
  - 用户点发送 → 乐观插入 `{ role:"user", text }` + `{ role:"assistant", streaming:true, text:"" }`。
  - 收 `cli_chunk(consult)` → 追加到当前 streaming 轮的 `text`。
  - 收 `consult_message` → 该轮 `streaming:false`，绑定 `raw_log_ref`（可 promote）。
  - `snapshot` 的 `consult.raw_log_refs` 是已落定轮的**真相源**：重连/刷新后从它重建历史轮（乐观态只在发送当轮用）。
- **分流**：`useProjectStream` 现在把所有 `cli_chunk` 塞一个缓冲；M3 要按 `kind` 分两路——workflow chunk 仍喂 `LiveChunks`，consult chunk 喂 `useConsult`。最小改动：`useProjectStream` 暴露 `cliChunks`（仅 workflow）与 `consultChunks`（仅 consult），或暴露原始流由 `useConsult` 自取。

### 3.4 右栏 `RightColumn.tsx` / 新 `ConsultPanel.tsx`
- 模型按钮 `Claude`：从 disabled 改为可点，点击 toggle consult 视图展开 / 收起（`active` 态高亮）。Gemini/Codex 仍 disabled。
- 新 `ConsultPanel`：
  - 顶部：「与 Claude 一问一答 · Haiku · 过程流，promote 才入证据库（非 gate 结论）」一行诚实说明。
  - 消息列表：`ConsultTurn` 卡片（user 气泡 + assistant 气泡）；assistant 流式时显打字态。
  - 每条 assistant 定稿轮：`AdapterBadge(claude)` + 「查看完整 transcript」(`RefChip`) + 「提升为 artifact」按钮（promote）。
  - 输入框：解锁；回车/按钮发送；发送中禁用 + 转圈；不可用时 disabled + 诚实提示。
- 底部原 M2 的 `disabled` 占位输入框移除（被 ConsultPanel 输入框取代）。

### 3.5 consult_note 在「关键产物」的诚实分区
- `RightColumn` 的 `STRUCTURED_ARTIFACTS`（gate 过的结论产物）**不动**。
- 新增独立分组「采纳笔记（consult，未过 gate）」渲染 `state.current.consult_note_refs`，每条用专属徽章/淡色，和上方结论产物视觉分隔。
- 语义提示：hover/小字注明「人工从对话采纳，未经 gate 校验，不计入证据覆盖」。**绝不**让它进证据映射 / 中栏结论。

### 3.6 promote 交互
- 点「提升为 artifact」→ 可选填一句 note → `promoteConsult` → 成功后该轮卡片显「已采纳为 consult_note」徽章 + 该轮按钮置灰（幂等，后端也去重）。
- 失败（如已 promote / 不是 consult raw_log）→ 行内诚实错误，不弹崩溃。

## 4. 两通道红线在 UI 的落地（M3 最重要）

| 通道 | UI 位置 | 能否当结论 |
| --- | --- | --- |
| consult 对话文本 / `cli_chunk(consult)` / consult raw_log | 右栏 ConsultPanel | ❌ 永远是过程流 |
| `consult_note`（人工 promote） | 右栏「采纳笔记」独立分区 | ❌ 人工采纳笔记，明确标「未过 gate」，**不**进证据映射 / 中栏结论 |
| gate 过的结构化 artifact | 中栏契约 / 证据映射 / 阶段状态 | ✅ 唯一可信结论 |

- consult 区任何文本**不得**被中栏引用；证据映射仍只来自 `claimEvidenceGate`（后端已天然排除 consult_note）。
- promote 是「人工标记我采纳了这段对话」，不是「把对话变成结论」——徽章与分区必须让这点一眼可辨。

## 5. 内部里程碑（建议顺序，跟随后端）

| 步 | 交付 | 依赖后端 | 验收 |
| --- | --- | --- | --- |
| F3.0 | 类型补全（`kind`/`consult`/`consult_note_refs`/`ConsultMessage`）；`sendConsult`/`promoteConsult` client | 端点形状（M3.3） | typecheck 绿；client 单测 |
| F3.1 | `useConsult` 流式拼接 + snapshot 重建；cli_chunk 按 kind 分流 | `cli_chunk(consult)`+`consult_message`（M3.3） | vitest：乐观插入 / 增量拼接 / 定稿替换 / 刷新重建 |
| F3.2 | `ConsultPanel` + 右栏 Claude 按钮接活 + 输入发送 + 流式打字态 | 后端异步 consult | 本地真跑：发消息拿 Haiku 回复、流式回显（手验 V7） |
| F3.3 | promote 按钮 + consult_note 独立分区徽章 + 不可用诚实态 | promote 端点 + state 字段 | promote 后徽章/置灰；不可用输入禁用、无 mock 假答 |

> 后端未就绪前，F3.0/F3.1 可用**假 cli_chunk(consult) / 假 consult_message** 驱动 UI 开发（mock 数据明确标注），但**上线前必须接真后端**，不留写死的假对话。

## 6. 测试

- `useConsult`：乐观用户消息、`cli_chunk(consult)` 增量拼接、`consult_message` 定稿替换、`snapshot` 重建历史轮、workflow/consult chunk 分流——vitest 纯逻辑测。
- `ConsultPanel`：发送禁用态、流式打字态、promote 按钮调用与置灰、consult_note 徽章渲染、不可用 disabled 提示——组件/纯函数测。
- consult_note **不**出现在结论产物区 / 证据映射的断言。
- 沿用 M1/M2 全部 vitest + typecheck 保持全绿。

## 7. 红线（与 M1/M2 一致 + M3 强调）

1. **结论只来自 gate 过的 artifact**；consult 文本与 consult_note 永远是「过程 / 采纳笔记」，不可当中栏结论。
2. **不让前端跑在后端能力前**：consult 输入只有后端 consult 端点就绪才解锁；不可用就诚实禁用。
3. **不改数据契约迁就 UI**：`state.consult` / `consult_note` / `cli_chunk.kind` 先在后端加并补测试，前端只镜像。
4. **不可用要诚实**：Claude 未接入就显「未接入」，**绝不**伪造一段对话或显 mock 回答（consult 与 workflow 降级不同）。
5. **mock 永远能跑**：后端未开 CLI 时面板照常工作（consult 禁用），不报错。
