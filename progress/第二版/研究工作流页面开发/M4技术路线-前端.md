# M4 技术路线（联调 + 指标面板）— 前端交接文档

本文档给**接手 M4 前端**的开发者。M4 前端就一件事：**把 `MetricsRow` 从「轻量 usage 透出」升级为完整运行指标面板 + 成本告警**——成本含 cache、接近预算 warn 高亮、超限 over 红条、当前阶段计时，全部诚实读后端真实数据。后端侧见同目录《M4技术路线-后端.md》。

前置：M1（指标行雏形）+ M2（`MetricsRow` 轻量 usage 透出：成本 / token tooltip）+ M3（consult）已完成（web vitest 全绿、typecheck 绿）。

> M4 前端**不新增流程视图**，是给 `MetricsRow` 补齐 §6.2 的运行指标并加告警态。重活在后端把数字算准，前端只渲染。

---

## 0. 一句话目标

```text
①成本细化展示：成本含 cache token，tooltip 拆 input/output/cache，不再标低估。
②预算告警：state.usage.budget.state = warn → 成本指标琥珀高亮 + 「接近预算上限」；
  = over → 红色 banner「已超会话预算，CLI 调用已暂停，请人工确认」。
③运行指标补齐：CLI 调用·失败 独立指标、当前阶段已用时（phase_started_at → now）。
④全部诚实：后端没给的（无 budget / 无计时）显「—」或不显，不前端造数。
```

对齐《指南》§6.2 面板运行指标 + §6.1 V10（成本可视含 cache + 告警）。

---

## 1. 范围

### 1.1 M4 前端必须做
- **成本细化**：`MetricsRow` 的「本会话成本」读细化后的 `state.usage.est_cost_usd`（已含 cache）；tooltip 拆 `input / output / cache_creation / cache_read` token；去掉 M2 的「低估」隐含语义。
- **预算告警**：
  - `state.usage.budget.state === "warn"` → 成本指标卡片琥珀边/底色 + 小字「接近预算上限（{ratio}）」。
  - `=== "over"` → 面板顶部红色 banner「已超会话预算（${spent}/${limit}），CLI 调用已暂停，请人工确认」。
- **指标补齐**：新增「CLI 调用 / 失败」指标（`usage.cli_calls` / `cli_failures`）；新增「当前阶段已用时」（`state.current.phase_started_at` → now，前端计时，1s tick）。
- **诚实缺省**：无 `usage` → 成本/调用「—」；无 `budget`（未配预算）→ 不告警；无 `phase_started_at` → 计时「—」。

### 1.2 M4 前端明确不做（v3+）
- 不做成本趋势图 / 历史曲线 / 多项目汇总。
- 「预计剩余时间」不做（后端不给真预测，显「—」）。
- 不动 consult / 工作流 / 证据映射等已完成视图（除非接新 usage 字段）。
- Gemini / Codex 维持占位。

## 2. 依赖的后端新数据（M4 后端提供，随 snapshot 来）

| 字段 | 形状 | 用途 |
| --- | --- | --- |
| `state.usage`（细化） | `+ cache_creation_tokens, cache_read_tokens`；`est_cost_usd` 含 cache | 成本细化 + tooltip |
| `state.usage.budget`（新增） | `{ limit: number|null, spent, ratio: number|null, state:"ok"|"warn"|"over" }` | 预算 warn/over 告警 |
| `state.usage.cli_calls / cli_failures`（已有） | number | 「CLI 调用/失败」指标 |
| `state.usage.by_phase`（已有，含 `consult`） | `Record<phase, bucket>` | tooltip 可选拆阶段 |
| `state.current.phase_started_at`（新增） | ISO string | 当前阶段已用时计时 |

> **不要前端造数**：无字段就显「—」/ 不显；前端只读 snapshot，不本地估算成本/预算（红线，与 M1/M2/M3 一致）。

## 3. 逐组件改动（`researchclaw/web/src/`）

### 3.1 `api/types.ts`
- `UsageSummary` 扩展（additive）：
  ```ts
  cache_creation_tokens?: number;
  cache_read_tokens?: number;
  budget?: { limit: number | null; spent: number; ratio: number | null; state: "ok" | "warn" | "over" };
  ```
  `by_phase` 桶同样可含 cache 字段（可选）。
- `ProjectCurrent` 加 `phase_started_at?: string`。

### 3.2 `MetricsRow.tsx`（升级，不重写）
- 成本卡片：值仍 `est_cost_usd`（现已含 cache）；tooltip 从「in/out tokens」扩为「in / out / cache 写 / cache 读 + CLI 调用/失败」。
- 告警态：依 `usage.budget.state` 给成本卡片加样式（`ok` 无样式 / `warn` 琥珀 / `over` 红）；`warn`/`over` 时卡片下方小字提示。复用现有 `Metric` 组件，加一个可选 `tone?: "ok"|"warn"|"over"` prop 控制边/底色。
- 新增指标卡片：
  - 「CLI 调用」`usage.cli_calls`（失败数作 tooltip 或副标）。
  - 「当前阶段已用时」：新 `PhaseTimer`（见 3.3）。
- 网格列数从 5 调整为容纳新卡片（响应式 `lg:grid-cols-6/7`），保持移动端两列。

### 3.3 `PhaseTimer`（新增小组件 / lib 纯函数）
- 输入 `phase_started_at`；用 `useEffect` + 1s `setInterval` 维护 now，显示 `mm:ss` / `h:mm:ss`。
- 无 `phase_started_at` 或 phase 为 `idle/blocked` → 显「—」。
- 计时纯函数 `elapsedLabel(startIso, nowMs)` 抽出可单测；组件只管 tick。

### 3.4 预算 over banner
- `over` 时在面板顶部（`Panel.tsx` 或 `CenterColumn` 顶）一条红 banner，复用 M2 降级 banner 的样式范式（amber → red）。文案：「已超会话预算（${spent}/${limit}）。CLI 调用已暂停，请人工确认后继续。」
- `warn` 不出 banner（只成本卡片高亮），避免打扰；`over` 才 banner（硬信号）。

## 4. 诚实与红线在 UI 的落地

| 情况 | UI |
| --- | --- |
| 未配预算（`budget.limit==null`） | 不告警，成本卡片正常；不显「接近上限」 |
| `warn` | 成本卡片琥珀 + 小字 ratio；不 banner |
| `over` | 成本卡片红 + 顶部红 banner「CLI 已暂停」 |
| 无 `usage`（没真跑过 CLI） | 成本/调用「—」，计时按 phase 决定 |
| cache 费率后端标「估算待核」 | tooltip 如实带「估算」字样，不假装精确 |

- 成本永远来自后端 `est_cost_usd`，前端**不**自己乘费率估算。
- 告警永远来自后端 `budget.state`，前端**不**自己定阈值判断。

## 6. 测试
- `elapsedLabel`：mm:ss / h:mm:ss / 缺起点显「—」——纯函数 vitest。
- `MetricsRow`：budget `ok/warn/over` 三态样式与 banner、无 budget 不告警、cache tooltip 文案、CLI 调用/失败渲染、无 usage 显「—」——组件/纯函数测。
- 沿用 M1/M2/M3 全部 vitest + typecheck 保持全绿。

---

## 7. 红线（与前序一致 + M4 强调）
1. **成本/告警只读后端**：前端不自算成本、不自定阈值；`est_cost_usd` 与 `budget.state` 是唯一真相源。
2. **诚实缺省**：没数据显「—」/ 不告警，不造数、不吓人（warn 温和、over 才硬提示）。
3. **不改数据契约迁就 UI**：cache / budget / phase_started_at 先在后端加并补测试，前端只镜像。
4. **不动已完成视图的结论性**：M4 只加指标/告警，不碰两通道、不把成本当结论引用。
5. **mock 永远能跑**：未接 CLI 时指标行正常（成本「—」、无告警），不报错。
