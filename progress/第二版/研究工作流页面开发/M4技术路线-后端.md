# M4 技术路线（联调 + 指标面板）— 后端交接文档

本文档给**接手 M4 后端**的开发者。M4 是 v2 收尾：把运行指标算准存好、成本估算细化（cache token 计价）、会话预算告警阈值透出、OpenClaw hook 触发改异步联调、产出 smoke log，最终让《第二版技术路线指南》§6.1 的 **V1–V10 全部达标**。前端侧（指标面板 + 成本告警 UI）见同目录《M4技术路线-前端.md》。

前置：M0 + M1 + M2（workflow 真实链路 + 成本护栏 + 降级）+ M3（consult 一问一答 + promote）已完成并测试通过。

> M4 后端**不引入新流程**，是「把已有数字算准 + 让已有触发器异步一致 + 给前端一个能直接渲染告警的 usage 结构」。重活在 M2/M3，M4 是打磨与联调。

---

## 0. 一句话目标

```text
①成本估算细化：把 cache_creation / cache_read token 纳入 CostTracker 与计价，
  不再只算 input/output（M2 已知低估），让面板成本是诚实值。
②预算告警：CostTracker 算出 budget 状态（ok / warn / over），随 state.usage 透前端，
  接近上限 warn、超限 over（CLI 调用已暂停）。
③运行指标算准：gate 通过率 / artifact 数 / 证据覆盖率 / CLI 调用·失败 / 当前阶段已用时，
  全部来自引擎真实数据，前端只读不算。
④OpenClaw hook 触发 start_research 改异步（复用 begin/execute），秒回不阻塞 ~38s。
⑤smoke log：一条真实端到端（contract_draft + consult）冒烟脚本，产联调证据。
最终 V1–V10 全绿。
```

对齐《指南》§6.1 V1–V10、§6.2 面板运行指标、§8 M4。

## 1. 范围

### 1.1 M4 必须做（后端）
- **cache token 计价**（§4）：`claudeCode.consume` 捕获 `cache_creation_input_tokens` / `cache_read_input_tokens`；`engine/cost.js` 的桶 + `estimateCostUsd` + `HAIKU_PRICING` 纳入 cache 费率；`snapshot` 透出 cache token 与更准的 `est_cost_usd`。
- **预算告警状态**（§5）：`CostTracker.budgetStatus(projectId)` → `{ limit, spent, ratio, state: "ok"|"warn"|"over" }`；并进 `state.usage.budget`。warn 阈值（默认 0.8）可配。
- **运行指标补齐**（§6）：当前阶段计时（`state.current.phase_started_at`）；其余（gate 通过率 / artifact 数 / 证据覆盖率 / CLI 调用·失败）已在 `phase_history` / `state.usage` / `/evidence`，M4 只确认算准并补缺口。
- **OpenClaw hook 异步**（§7）：`orchestrator.handle` 的 `start_research` 分支改用 `beginDraftFromText` + 后台 `executeContractRun`（接 Claude 时），秒回 ack 不阻塞 hook。
- **smoke log**（§8）：`npm run smoke:claude`（显式开关下）跑一条真实 contract_draft + 一轮 consult，落 smoke 日志（phase / artifact / cost / 降级），作 V1–V10 联调证据。
- **V1–V10 验收映射**（§9）：逐条对应到测试 / 手验位置。

### 1.2 M4 明确不做（v3+）
- 不接 Gemini / Codex（维持占位）；不接其余 phase 的真实 CLI（接口已通用，按需 opt-in，不在 M4 强制）。
- 不做多 worker 并行 / 多 agent 互投票 / 长期记忆库 / 数据库。
- 「预计剩余时间」不做真预测（§6：经验值或留空，诚实标「—」）。

## 2. 架构变化与改动模块

```text
ClaudeCodeAdapter.consume（M2/M3）  ── 捕获 cache_* token ──┐
                                                            ▼
engine/cost.js  CostTracker
  ├─ record(usage{input,output,cache_creation,cache_read}, phase)  ← 桶纳入 cache
  ├─ estimateCostUsd(... HAIKU_PRICING{input,output,cache_write,cache_read})  ← 计价细化
  ├─ snapshot()  → { ...tokens, cache_creation_tokens, cache_read_tokens, est_cost_usd, budget }
  └─ budgetStatus(projectId) → { limit, spent, ratio, state }    ← 新增
        ▲
engine/orchestrator.js
  ├─ persistUsage(state)  → state.usage = snapshot()（含 budget，M4 扩展）
  ├─ handle().start_research → begin + 后台 execute（M4 改异步）
  └─ phase 切换处写 state.current.phase_started_at（M4 加，计时用）

scripts/smoke-claude.js（新增）  → 真实端到端冒烟 + 落 log
```

改动文件：
- `adapters/claudeCode.js` — `consume` 捕获 cache token（其余不变）。
- `engine/cost.js` — `HAIKU_PRICING` 加 cache 费率；桶/`estimateCostUsd`/`snapshot` 纳入 cache；新增 `budgetStatus`。
- `engine/orchestrator.js` — `persistUsage` 带 budget；`start_research` 异步；phase 计时字段。
- `gateway.js` / `server.js` — hook 路径异步对接（若需要返回 ack 形态调整）。
- `scripts/smoke-claude.js`（新增） + `package.json` 加 `smoke:claude`。

不动：gate 逻辑、workflow、consult 主体、`ModelAdapter` 接口、两通道边界。

## 3. ModelAdapter / usage 形状（向后兼容扩展）

`usage` 在 M2 是 `{ input_tokens, output_tokens, model, turns, duration_ms }`。M4 **additive** 扩展（旧字段不变，旧测试不破）：
```js
usage = {
  input_tokens, output_tokens,
  cache_creation_input_tokens,   // M4 新增（result.usage 里有，M2 丢弃了）
  cache_read_input_tokens,       // M4 新增（实测占大头）
  model, turns, duration_ms
}
```
`state.usage`（snapshot）扩展：
```js
state.usage = {
  input_tokens, output_tokens,
  cache_creation_tokens, cache_read_tokens,     // M4 新增
  est_cost_usd,                                  // M4 起含 cache，不再低估
  cli_calls, cli_failures,
  by_phase: { contract_draft:{...}, consult:{...} },   // 桶同样含 cache
  budget: { limit, spent, ratio, state }         // M4 新增；无预算时 limit:null,state:"ok"
}
```

> 缺字段容错：老 fixture 没有 cache_* → 视为 0；前端无 `budget` → 视为 `ok`。

## 4. cache token 计价细化（M2 已知低估的修复）

**背景**（M2进度交接 §7）：真实 result usage 里 `input_tokens` 才十几，**大头是 `cache_read_input_tokens`（实测 ~37k）**；M2 的 `est_cost_usd` 只算 input+output → 系统性低估。

实现：
1. `claudeCode.consume`：`result` 事件里把 `event.usage.cache_creation_input_tokens` / `cache_read_input_tokens` 一并取出（当前只取了 input/output）。
2. `engine/cost.js`：
   - `HAIKU_PRICING` 加 cache 费率：
     ```js
     // 以 Anthropic 公布的 Haiku 费率为准；cache write 通常 = 1.25×input，cache read ≈ 0.1×input。
     // 实现时以官方文档/账单核对的真实数值为准，注释标注来源与核对日期。
     export const HAIKU_PRICING = {
       input: 1.0/1e6, output: 5.0/1e6,
       cache_write: 1.25/1e6, cache_read: 0.1/1e6
     };
     ```
   - `emptyBucket()` / `record` 加 `cache_creation_tokens` / `cache_read_tokens` 累计。
   - `estimateCostUsd` 纳入：`+ cache_creation*cache_write + cache_read*cache_read`。
   - `snapshot` 透出 cache token 总量 + 更准 `est_cost_usd`。
3. consult（M3）用量同样走 `record`（phase `consult`），cache 一并计。

> **诚实**：费率必须以官方文档/真实账单核对，注释写明来源与核对日期，不拍脑袋。若某费率暂不确定，宁可在 tooltip/注释标「估算，cache 费率待核」也不静默写错。

## 5. 预算告警状态（budgetStatus）

- `CostTracker` 已有 `sessionBudgetUsd` + `overBudget`。M4 加分级：
  ```js
  budgetStatus(projectId) {
    const spent = this.snapshot(projectId).est_cost_usd;
    if (this.sessionBudgetUsd == null) return { limit:null, spent, ratio:null, state:"ok" };
    const ratio = spent / this.sessionBudgetUsd;
    const state = ratio > 1 ? "over" : ratio >= this.warnRatio ? "warn" : "ok";
    return { limit:this.sessionBudgetUsd, spent, ratio, state };
  }
  ```
  `warnRatio` 默认 0.8，可经 env `RESEARCHCLAW_BUDGET_WARN_RATIO` 配。
- `persistUsage` 把 `budgetStatus` 塞进 `state.usage.budget`，随 snapshot 到前端。
- 硬停仍是 `overBudget`：workflow/ consult 在 over 时拒绝/降级（已有）；M4 只是把 warn/over **可视化信号**透出，让人在硬停前就看到。

## 6. 运行指标（§6.2 对照，确认算准）

| 指标 | 来源 | M4 动作 |
| --- | --- | --- |
| 总体进度 % | `phase_history`（已 pass / 总阶段） | 已有（前端 `pipeline.ts`），确认 |
| gate 通过率 | `phase_history` pass/(pass+fail) | 已有，确认 |
| 证据覆盖率 | `/evidence`（claimEvidenceGate） | 已有，确认 |
| artifact 数 | state.current 结构化 ref 数 | 已有，确认（consult_note **不计入**结论 artifact 数，单独算或不算） |
| 本会话 token / 成本 | `state.usage`（含 cache，§4） | **细化**：cache token + 更准 cost |
| CLI 调用 / 失败 | `state.usage.cli_calls / cli_failures` | 已有（含 consult），确认透出为独立指标 |
| 当前阶段已用时 | `state.current.phase_started_at` → now | **新增**：phase 切换时写 `phase_started_at`；前端算 elapsed |
| 预计剩余 | — | 不做真预测，留「—」（§1.2） |

> phase 计时落点：每次 `state.phase = X` 的同处写 `state.current.phase_started_at = nowIso()`（集中到一个 helper，避免散落漏写）。

## 7. OpenClaw hook 触发改异步（联调一致）

**现状**（M2进度交接 §7）：`gateway.handleOpenClawPayload` → `orchestrator.handle(signal)` → `start_research` 走**同步** `startResearch`；接 Claude 时阻塞 hook ~38s。

改法：
- `orchestrator.handle` 的 `case "start_research"`：改为「`_intake` → 若 ready 则 `beginDraftFromText` 式秒回 + 后台 `executeContractRun`」，与 dashboard `/start` 一致。hook 立即拿到 `running` ack，不等起草跑完。
- `handle` 是 `async` 且 hook 是 fire-and-forget，所以返回体可带 `running:true`；后台 `executeContractRun(projectId).catch(()=>{})`（同 server.js `/start` 写法）。
- **保留同步 `startResearch`** 给 `startFromText` / 既有同步测试用，不删（M2 既定取舍）。M4 只切 hook 这一条触发路径。

测试影响：
- gateway / hook 测试若断言「handle 后 contract 已起草」需改为「handle 后 phase=contract_draft + running，再 `executeContractRun`/轮询到定稿」——复用 `tests/helpers.js` 的 `startAndWait` 轮询范式（M2 已为 `/start` 引入）。
- mock 下 `executeContractRun` 极快，轮询几乎立即返回，测试不慢。

## 8. smoke log（联调证据）

- `scripts/smoke-claude.js`（仅 `RESEARCHCLAW_ENABLE_CLAUDE=1` + 有 provider 时跑）：
  1. 建临时项目 → `beginDraftFromText` + `executeContractRun`（真实 Haiku 起草 contract）→ 等过 gate。
  2. approve contract。
  3. `beginConsult` + `executeConsult` 跑一轮真实 consult → promote 一轮为 consult_note。
  4. 打印 / 落 `logs/smoke-<ts>.json`：每步 phase、artifact ref、`state.usage`（token/cost/cache/budget）、是否降级、耗时。
- `package.json` 加 `"smoke:claude": "RESEARCHCLAW_ENABLE_CLAUDE=1 node scripts/smoke-claude.js"`。
- **不进 CI**（真调 CLI、花钱）；是本地联调 / 验收 V1–V10 的可复现证据。

## 10. 测试要求（CI 不真调 CLI，零额度）

- **cache 计价**：`consume` 从 result fixture 取出 cache_*；`estimateCostUsd` 含 cache；`snapshot` 透出 cache token；用一条「cache 占大头」的 fixture 断言 cost 不再低估。
- **budgetStatus**：null 预算 → ok；ratio 0.8 边界 → warn；>1 → over；进 `state.usage.budget`。
- **hook 异步**：`handle(start_research)` 秒回 `running` + phase=contract_draft；`executeContractRun` 后 contract 定稿（mock 轮询）；既有同步 `startResearch` 测试保留。
- **phase 计时**：phase 切换写 `phase_started_at`；不破坏既有快照测试。
- **指标算准**：gate 通过率 / artifact 数 / 证据覆盖率 / cli_calls·failures 在多场景下数值正确（含 consult 计入 cli_calls）。
- 沿用 M0/M1/M2/M3 全部测试保持全绿；CI 默认全 mock、零额度。smoke 脚本仅本地/显式开关。

## 11. 红线（务必遵守）

1. **成本要诚实**：cache 费率以官方/账单核对，不静默写错；低估是 bug，不是「保守」。
2. **两通道不破**：M4 不新增任何「从对话提炼结论」的路径；指标只读引擎真实数据，不前端造数。
3. **engine 边界**：hook 异步仍只在 orchestrator 写 state；adapter 不改 research state；`ModelAdapter` 接口不变。
4. **默认 Haiku**；budget warn/over 只是可视信号，硬停仍由 `overBudget` 兜。
5. **mock 永远是回放底座**：CI 零额度；smoke 真调仅显式开关；不接 CLI 时所有指标仍有合理值（cost「—」、budget ok）。
