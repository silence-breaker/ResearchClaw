## 2.5 ⚠️ 一处超出纯前端的改动(必读,交接重点)

**改了 `fixtures/contracts/valid.json` 的 `claim_evidence_map`(demo 契约的输入数据)。**

**为什么改**:原 demo 契约**只有一条 claim C1**,其要求的三条证据(`baseline result` / `same-split comparison` / `main metric table`)全是**实验阶段**才产出的东西。而 v2 明确不做实验/复现执行阶段(技术路线指南 §3.2),`gates.js` 证据登记表把它们标为 `inScope:false` —— 即 v2 里**永远没有 artifact 能满足**。后果:证据映射 tab 会**恒显 0% 覆盖、全是缺口**,不管流水线跑多远,演示不出"证据命中 artifact"这个护城河卖点。

**怎么改**:保留 C1 作为诚实的"范围外缺口"示例,新增 C2–C6,其要求的证据是 v2 范围内能产出的:

| claim | required_evidence | 由谁满足 |
|---|---|---|
| C2 | literature survey | paper_cards(文献侦察) |
| C3 | selected baseline | baseline_decision(基线选择) |
| C4 | reproduction checklist | reproduction_checklist(复现清单) |
| C5 | idea proposal | idea_cards(想法生成) |
| C6 | novelty assessment | idea_review_report(想法评审) |

(注:phrase 须避开会被前置规则误匹配的词。如 `idea review` 会先命中 `/idea/` → idea_cards,故 C6 用 `novelty assessment` 才正确映射到 idea_review_report。映射规则见 `engine/gates.js` 的 `evidenceRegistry`。)

**为什么不违红线**:
1. `claimEvidenceGate` **算法一个字没动** —— 证据映射仍是真算,绝非伪造/写死。
2. 改的是 demo **输入数据**(样例契约),不是写死"结论"。
3. 无任何测试因此挂(schema 只要求 `claim_evidence_map` 非空;`contractFixture()` 的 C1 断言仍成立)。
4. 让护城河功能能用**真实计算**演示满足 vs 缺口的增长。

**实测效果**:流水线推进时覆盖率真实增长 **25%(文献+基线后) → 63%(summary 后)**;C2/C3 由真实 paper_cards/baseline_decision artifact 命中,C1 始终为诚实缺口。

**如何回退**:若想恢复成单 C1(覆盖率恒 0%),只需把 `fixtures/contracts/valid.json` 的 `claim_evidence_map` 删回原来的一条 C1 即可,前后端代码无需动(证据映射会照常工作,只是全缺口)。

## 4. 必须守住的红线(摘自《M1技术路线-前端详化》§11)

1. **结论只来自 artifact。** 面板任何"结论"必须能点到对应 artifact ref;证据映射(M1.4)用 `claimEvidenceGate` 真实输出,**不许写死**(已遵守:走 `/evidence` 只读端点真算,见 §2.5)。
2. **不让前端跑在后端能力前。** 右栏 CLI 对话是 M3,M1 老实 disabled 占位。
3. **不改数据契约迁就 UI。** 需要新字段先在后端加并补测试,engine 仍是唯一状态源。前端只调 HTTP/SSE,不直接操作 state。
4. **mock 永远能跑**:任何改动后 `demo:fixture` 与两套 `npm test` 必须仍绿;CI 全 mock、零模型额度。
5. **默认模型** claude-haiku-4-5,**绝不**默认 Opus。
6. **不要急着删 `ui.js`**:新旧面板共存(`/` vs `/app`),M1 末再切默认入口。

## 5. 已知限制 / 坑(交接重点)

- **mock 不重写契约内容**:`revise` 时 mock 把反馈存入 `human_notes` 并版本 +1,但**不会**用反馈改写 research_question/hypothesis/成功标准(那需真实模型)。所以浏览器里修订后,可见变化是"版本号递增 + 修订记录追加",主体字段不变 —— 这是 mock 模式预期,非 bug。
- **recover 无法用全 mock 复现**:gate 在 mock 下永远 pass,进不了 `blocked` 态,所以"点回退恢复按钮"这条 UI 路径无法用 mock 在浏览器手验。其派生逻辑(`deriveActions` 单测)、端点(后端测试)、客户端函数均已覆盖。如需手验,要先造一个 blocked fixture(尚未写,见下"下一步可选")。
- **`.researchclaw/projects/` 里有外部产生的项目**:`proj_openclaw_*`、`proj_demo_001` 等。其中 `proj_openclaw_*` 由 openclaw hook 集成在跑时产生,非手动创建,清理需谨慎(红线:不删非自己创建的东西)。
- **后端进程残留坑**:若某个旧 `server.js` 进程长期占着 8787(早于 `/app` 路由的版本),会导致 `/app` 返回 404 且新进程 `EADDRINUSE`。排查见《启动指南》第 6 节。
- **证据映射 = 实时预览,非状态机产物**:`/evidence` 是只读端点,每次按 `state.updated_at` 重算 `claimEvidenceGate`;它**不写 state、不入证据链**。summary 阶段产出的 `summary.content.evidence_index` 才是落档的那份。两者算法同源,数值一致。
- **demo 契约已被改成 6 条 claim**:见 §2.5。这是为了让证据映射能演示满足/缺口对比;真实接 CLI(M2)后契约由模型产出,这条 demo fixture 的影响仅限纯 mock 演示。

## 6. 下一步:M2(ClaudeCodeAdapter workflow 模式)

M1(含 M1.4、M1.5 占位打磨)已收口。按《第二版技术路线指南》§8 里程碑,下一步是 **M2**:

| 交付 | 要点 |
| --- | --- |
| `ClaudeCodeAdapter` | headless 调 Claude Code,**默认 Haiku**(绝不默认 Opus),forced schema(要求写 out.json + 读文件校验) |
| 沙箱隔离 | 每次 CLI 运行限定独立工作目录 / git worktree,受限 `--allowedTools` |
| 成本护栏 | token/turn/超时上限;无 key 或超限**优雅降级 mock**,不崩 |
| 验收 | contract_draft 由真实 Haiku 产出并过 contract gate;非法输出被拦不直接 commit |

接入点已就绪:`ResearchOrchestrator` 注入的 adapter 接口不变(`MockModelAdapter` → 可选 `ClaudeCodeAdapter`),workflow 层零改动(指南 §2.2)。

### M1 收尾的两个小尾巴(可选,不阻塞 M2)
- **证据覆盖率与 SSE 解耦**:`EvidenceMapTab` / `MetricsRow` 用 `useQuery(['evidence', id, updated_at])` 跟随 state 变化重取,目前够用;若以后 evidence 有 granular 事件可改成 SSE 推送。
- **制造 blocked 态的 fixture 脚本**:仍未写。gate 在 mock 下永远 pass,recover 回退按钮这条 UI 路径无法用 mock 在浏览器手验(派生逻辑/端点/客户端均已测)。
