## 1. 一句话现状

**M3 consult 一问一答与 M4 指标/联调能力均已落地。** 右栏 Claude 可打开真实 consult 面板，发送问题后走 `POST /projects/:id/consult`，后端后台执行 `ClaudeCodeAdapter.consult()`，通过 `cli_chunk(kind:"consult")` 流式回显，整轮落 `raw_log(workflow:"consult")`；人工 promote 后生成 `consult_note`，但仍明确为「采纳笔记，未过 gate」，不进入结论/证据映射。M4 侧已补齐 cache token 计价、budget ok/warn/over 状态、CLI 调用/失败、当前阶段计时、OpenClaw hook 异步起草和真实 smoke 脚本。

```bash

# 真实 CLI 冒烟（花 Haiku 额度，需显式开关）
```

### 2.1 后端链路

| 文件 | 已落地能力 |

| `researchclaw/engine/orchestrator.js` | 新增 `beginConsult` / `executeConsult` / `_executeConsult` / `landConsultRawLog` / `promoteConsult`；`consultChain` 按项目串行；consult 只写 `state.consult` 与 raw_log，不推进 phase/gate。 |
| `researchclaw/server.js` | 新增 `POST /projects/:id/consult`（秒回 ack + 后台跑）和 `POST /projects/:id/consult/promote`；SSE 原通道转发 `cli_chunk` / `consult_message` / `snapshot`。 |
| `researchclaw/evidence/types.js` | artifact type 增加 `consult_note`，注释明确它只用于可溯源采纳，不是 gated conclusion。 |
| `fixtures/cli/consult.stream.jsonl` | consult stream-json fixture，含 `session_id`、assistant 文本块、cache usage，供 CI stub 回放。 |

关键语义：

- `ClaudeCodeAdapter.consult()` 返回 `{ ok, session_id, text, usage, raw }`，失败返回 honest error（如 `timeout` / `empty_reply`），不回退 mock。
- `beginConsult()` 对空消息、无 consult adapter 返回 `{ ok:false, running:false, error }`，这是预期不可用态。
- `_executeConsult()` 成功后落 consult raw_log，更新 `state.consult = { session_id, turn_count, last_turn_at, raw_log_refs }`，记录 `CostTracker` phase=`consult`，再发 `consult_message` 与 snapshot。
- `promoteConsult()` 只允许 promote `raw_log + workflow:"consult"`；同一 raw_log 幂等返回已有 `consult_note`；不改 `phase`、不写 `phase_history`、不进 `artifactTypeByStateKey`。

## 3. M4 已完成：指标、成本、hook 异步与 smoke

### 3.1 后端指标与成本

| 文件 | 已落地能力 |
| --- | --- |
| `researchclaw/adapters/claudeCode.js` | `consume()` 解析 `cache_creation_input_tokens` / `cache_read_input_tokens`，usage 形状向后兼容。 |
| `researchclaw/engine/cost.js` | `HAIKU_PRICING` 增加 cache write/read；`estimateCostUsd()` 纳入 cache；bucket 记录 cache tokens；`budgetStatus()` 输出 `{ limit, spent, ratio, state }`。 |
| `researchclaw/engine/orchestrator.js` | `persistUsage()` 写入含 budget/cache 的 `state.usage`；`stampPhaseStart()` 在 phase 变化时写 `state.current.phase_started_at`。 |
| `researchclaw/server.js` | `buildAdapter()` 创建 `CostTracker`；budget 上限仍由 `RESEARCHCLAW_SESSION_BUDGET_USD` 配置。 |

重要细节：

- `CostTracker.snapshot(projectId)` 即 `state.usage` 真相源，含 `input_tokens`、`output_tokens`、`cache_creation_tokens`、`cache_read_tokens`、`est_cost_usd`、`cli_calls`、`cli_failures`、`by_phase`、`budget`。
- `budgetStatus()` 默认 warn 阈值为 0.8；`overBudget()` 使用 `budgetStatus().state === "over"`。
- 当前代码构造 `CostTracker` 时只传了 `sessionBudgetUsd`，未把 `RESEARCHCLAW_BUDGET_WARN_RATIO` 接入构造；如要调整 warn 阈值，需要补一行 env 解析。
- `stampPhaseStart()` 用进程内 `lastPhase` 判断 phase 是否变化。重启后第一次写同一 state 时可能重盖 `phase_started_at`，这是目前的轻量实现取舍。

### 3.2 OpenClaw hook 异步

`researchclaw/engine/orchestrator.js` 的 `handle(signal)` 中 `start_research` 已改为：

1. `beginResearch(state, signal)` 完成 intake、设置 `phase=contract_draft`、写 `phase_running` pending action。
2. 秒回 ack：`actions:["contract_draft_running"]` + `needs_draft:true`。
3. 后台 `executeContractRun(projectId).catch(() => {})`。

这使 hook 路径与 dashboard `/start` 的「ack 快返 + 后台起草 + SSE 过程流」一致，不再等待真实 Claude 起草完成。

## 5. 红线遵守情况

1. **consult 不推进 research state**：实际只写 `state.consult`、`raw_log_artifact_refs` 与 usage；`phase` / `phase_history` / gate 不因 consult 改变。
2. **consult_note 不当结论**：后端不把它加入 `artifactTypeByStateKey`，前端不把它加入 `STRUCTURED_ARTIFACTS`，右栏单独分区标「未过 gate」。
3. **结论仍只来自 gated artifact**：中栏契约/证据映射/summary 仍走结构化 artifact 与 `claimEvidenceGate`。
4. **不可用诚实**：consult 无 adapter/空消息返回 honest error；前端显示错误，不 mock 一段回答。
5. **默认 Haiku**：`server.js` 仍通过 `resolveClaudeModel()` / provider 配置选择模型，非 Haiku 打 warning；consult 与 workflow 共用同一 model config。
6. **CI 零额度**：真实 CLI 只在 `RESEARCHCLAW_ENABLE_CLAUDE=1` 时启用；测试走 stub/fixture/mock。

## 6. 已知限制 / 接手注意

- **warnRatio env 尚未接线**：M4 路线提到 `RESEARCHCLAW_BUDGET_WARN_RATIO`，但 `server.js buildAdapter()` 当前没有读取它；默认 0.8 生效。若要配置化，改 `new CostTracker({ warnRatio: Number(...) })` 并补测试。
- **真实 consult 可用性取决于 adapter 是否暴露 consult**：默认不开 `RESEARCHCLAW_ENABLE_CLAUDE` 时 `buildAdapter()` 返回 `MockModelAdapter`，无 `consult()`，前端会收到「Claude 未接入」。这是设计内 honest state。
- **RoutingAdapter 只让 contract_draft 走真实 workflow**：`server.js` 里 `phases:["contract_draft"]`；consult 直接依赖 primary/routing adapter 是否实现 `consult()`。如未来 routing adapter 未转发 consult，需要检查 `researchclaw/adapters/route.js`。
- **后台 Map 仍是进程内**：`inflight`、`pendingRun`、`consultChain`、`lastPhase`、`CostTracker` 都不是 durable worker 队列；进程重启后 running/预算门的 live 上下文会丢，state.json 只保存快照结果。
- **PhaseTimer 重启语义**：`phase_started_at` 只在 orchestrator 写 state 时维护；进程重启后 `lastPhase` 空，下一次 write 可能把当前 phase 起点刷新为新时间。
- **ConsultPanel 不做多会话/tab**：每项目单一 consult 线，`state.consult.raw_log_refs` 按序显示；M3 技术路线明确把多会话留到 v3+。
- **Promote note 输入未做 UI**：路线中提到可选 note；当前按钮直接调用 `promoteConsult(projectId, refValue)`，未弹出 note 输入框。后端与 API 已支持 `note` 参数，UI 可后续补。
- **smoke 会写真实项目与日志**：`smoke-claude.js` 使用 `FileEvidenceStore()`，会在默认 `.researchclaw/projects` 下建 `proj_smoke_<pid>`，并写 `logs/smoke-*.json`；清理前确认不是需要保留的验收证据。
