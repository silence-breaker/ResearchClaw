## 2. ⚠️ 必读：本机模型/中转站配置（M3 接 CLI 会再次踩到）

本机 Claude Code 走 **cc-switch 中转站**（`ANTHROPIC_BASE_URL=https://www.packyapi.com`），配置写在 `~/.claude/settings.json` 的 `env` 块（`claude` 启动时自己读，**普通 `npm run dev` shell 不会自动 export**）。三个坑：

1. **中转站默认 `ANTHROPIC_MODEL` 是 Opus**（`claude-opus-4-8`）。绝不能让 headless `claude -p` 跟默认走 → 必须显式 `--model` 指定 Haiku（成本红线）。
2. **中转站的 Haiku 是带日期全 ID `claude-haiku-4-5-20251001`**，裸别名 `claude-haiku-4-5` 不被接受（会 503/挂死）。该 ID 在 `settings.json` 的 `ANTHROPIC_DEFAULT_HAIKU_MODEL`。
3. **`server.js` 在普通 shell 里取不到 settings.json 的 env** → 已用 `adapters/claudeConfig.js` 的 `resolveClaudeModel()` 兜底直接读 settings.json。优先级：`RESEARCHCLAW_MODEL` → 进程 env `ANTHROPIC_DEFAULT_HAIKU_MODEL` → settings.json 的同名 → 裸别名。**M3 接其它 phase 沿用同一解析，别再硬写裸别名。**

启动方式（不用再手设模型）：
```bash
RESEARCHCLAW_ENABLE_CLAUDE=1 npm run dev      # 默认全 mock；加这个开关才接真实 CLI
```
认证走中转站 token（`ANTHROPIC_AUTH_TOKEN`），所以 `ClaudeCodeAdapter.isAvailable()` 判定是「`claude` 二进制是否存在」，**不强求 env 有 API key**。

## 5. 异步化改造（M2 后期，解决「卡住 + 看不到进度」）

**问题根因**（实测定位）：
1. `server.js` 取不到中转站 Haiku id → 退回裸别名 → CLI 503 挂死 → `/start` 同步阻塞 → 「创建中」卡死。
2. 即使模型对，`contract_draft` 在 `/start` 里**同步跑完 ~38s** 才返回，面板要等返回后才 navigate、才连 SSE → 所有 `cli_chunk` 在「无订阅者」时发完丢了（EventBus 原无缓冲）。

**修复**：
- 模型解析兜底读 settings.json（§2）。
- EventBus 加 cli_chunk 回放缓冲；SSE 连接时补发。
- orchestrator 异步拆分：`/start`→`beginDraftFromText`（秒回 `phase=contract_draft` + `phase_running` pending + `needs_draft:true`）→ 后台 `executeContractRun`（真实起草 + 实时 cli_chunk + 最终 snapshot）。`/revise` 同理。**`startResearch`/`revise`/openclaw 仍同步，老测试零改动**。
- 前端「运行中」转圈 + 右栏实时滚动。

**实测**：`beginDraftFromText` 5ms 秒回；真实 Haiku 后台起草 → cli_chunk 实时 → `contract_review` + `adapter:claude` + $0.0206。

> **设计取舍**：保留同步 `startResearch`/`revise` 供 openclaw hook 与既有测试用（hook 不在意 38s 阻塞），仅 dashboard 的 `/start`/`/revise` 走异步。这样动状态机但不破坏 53 个老测试。`pendingRun`（draft/revise 上下文）+ `inflight`（去重）均为**进程内 Map**，重启即丢（运行中崩溃需重新发起）。

## 6. 红线遵守（逐条）
1. **两通道物理分离**：结论只来自 `out.json → schema → gate` 的结构化 artifact；stream-json transcript 一律 `raw_log`（`landCliRawLog`），永不当结论。
2. **engine 边界**：adapter 不写 research state；`ModelAdapter.run` 签名不变；state 只在 orchestrator 写。
3. **默认 Haiku，绝不默认 Opus**：`resolveClaudeModel` 永不取 `ANTHROPIC_MODEL`（中转站默认是 Opus）；非 Haiku 告警。
4. **mock 永远是回放底座**：真实 CLI 仅 `contract_draft` opt-in；不开开关全 mock；CI 零额度（stub 子进程回放 fixture）。
5. **沙箱 + 受限 allowedTools + redactSecrets**：transcript 落档脱敏，不写密钥。
6. **降级诚实**：回退 mock 后产物 `adapter:"mock"` + `degraded`，面板如实显示 banner。

## 7. 已知限制 / 坑（交接重点）

- **成本是估算**：`est_cost_usd` 只算 `input_tokens + output_tokens`。真实 result usage 含 `cache_creation_input_tokens` / `cache_read_input_tokens`（实测占大头，input_tokens 才 16，cache 读 ~37k），未单独计价 → 当前显示是**低估**。M4 成本面板可细化（不同 cache 费率）。
- **openclaw hook 路径仍同步**：keyword-detector 触发 `start_research` 走同步 `startResearch`，接 Claude 时会阻塞 hook 响应 ~38s。hook 是 fire-and-forget，暂可接受；要做也可复用 begin/execute 改异步。
- **后台写 state 的并发**：`executeContractRun` 后台写 state，与用户在起草中点归档/删除理论上有竞态（mock 下极快、inflight 去重已缓解；测试用 `startAndWait` 轮询规避）。M3+ 若加更多后台阶段需正视（指南 §10 的 state 串行化兜底）。
- **`pendingRun`/`inflight`/`CostTracker` 在内存**：进程重启丢失；`state.usage` 已持久化在 state.json（会话级），但 CostTracker 重启清零（预算门重新计）。
- **fixture 是增强版而非原始 65KB 捕获**：`fixtures/cli/contract-draft.stream.jsonl` 手工保留了真实形态的代表性事件（hook/thinking_tokens/thinking/cache usage），解析器对这些已实测容忍；不想塞整段噪声。
- **真实 CLI 会被注入 SessionStart hook 噪声**：本机 superpowers hook 会把一大段 context 注入到 spawn 出来的 `claude`（transcript 里能看到），解析器忽略，无害。
- **demo 契约仍 6 条 claim**（M1.6 §2.5）：纯 mock 演示用；真实接 CLI 后契约由模型产出。
