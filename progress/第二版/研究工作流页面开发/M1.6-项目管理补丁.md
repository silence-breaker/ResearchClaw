# M1.6 项目管理补丁（删除/归档 + intake 补录）— 交接文档

本补丁与 M2 平行但**独立**：它修两个横切的项目管理问题，和「接入真实 Claude Code」无关，可单独先做。前后端分别写清（§A 后端 / §B 前端）。

> 触发背景（2026-06-04 用户反馈）：
> 1. **无法删除已建立的项目** —— 后端根本没有删除/归档能力（无端点、无 store 方法、无 UI）。
> 2. **`proj_openclaw_5ad8eedb9f6c` 卡在「研究契约」无法推进** —— 实测该项目 `phase=intake`、`pending=provide_research_direction`：它由 openclaw hook **无主题**创建，引擎正确地停在 intake 等待研究方向；但面板 `deriveActions` 当初把 `provide_research_direction` 丢弃了（`lib/actions.ts:56-58` 注释「not part of M1.3」），导致面板渲染不出任何控件 → 看似卡死。

---

## 0. 两项决策（已与用户确认）

1. **删除语义：软删（归档隐藏，可恢复）为默认。** 标准回收站模式：归档 = 打 `archived` 标记、列表隐藏、文件保留、可「恢复」；在「已归档」视图里另提供**彻底删除（二次确认，不可恢复）**作为最终清盘出口。
2. **intake 卡住：面板加补录入口。** 面板检测到 `provide_research_direction` 待办时渲染一个「输入研究方向」输入框，提交后复用既有 `POST /projects/:id/start` 让引擎从 intake 续走到起草契约。从根上修复所有此类项目。

## A. 后端

### A.1 范围
- 软删/归档/恢复/彻底删除的 store 方法 + HTTP 端点 + 测试。
- intake 补录**不需要新后端逻辑**：`POST /projects/:id/start` 带 `research_direction` 再调一次，`orchestrator.startFromText → startResearch` 会重置 `current` 并推进到 `contract_draft`（已验证现有行为，见 `engine/orchestrator.js:129-170`）。本补丁只需为「在已有 intake 项目上 /start 能续走」补一条回归测试。

### A.2 `evidence/store.js`（新增方法）

`archived` 标记直接落在每个项目的 `state.json`（per-project 已是唯一真相源；这是后端字段、engine 仍是状态源，先加 + 补测试，符合红线）。归档是**元操作**，不走 orchestrator 的研究状态机（不 bump version、不 recordPhase、不 emit snapshot）——store 直接读 state.json 打标回写。

```js
// 读 state.json → 设/清 archived → 写回（不动 phase/version/history）
archiveProject(projectId)   // state.archived = true;  state.archived_at = nowIso()
unarchiveProject(projectId) // delete state.archived;   delete state.archived_at
deleteProject(projectId)    // 递归删除 projectDir(projectId) 整个目录（彻底，不可恢复）
```

- `deleteProject` 用 `fs.rmSync(dir, { recursive: true, force: true })`；删前可校验 `dir` 在 `this.rootDir/projects/` 之内（防越界）。
- `listProjectSummaries()`：在每条 summary 里**带上 `archived: boolean`**（默认 false）。**不在 store 层过滤**——让 API/前端决定显示哪批，保持 store 纯粹。

### A.3 `server.js`（新增端点，照现有 `recover` 路由写法）

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/projects/:id/archive` | `store.archiveProject(id)` → `{ ok:true }` |
| POST | `/projects/:id/unarchive` | `store.unarchiveProject(id)` → `{ ok:true }` |
| POST | `/projects/:id/delete` | `store.deleteProject(id)` → `{ ok:true }`（彻底删除） |

- `GET /projects` 现状返回全部；本补丁让其每条带 `archived` 字段（前端据此分组）。如需服务端过滤，可选支持 `?archived=1` 只列归档项；**默认返回全部 + 带标记**即可，前端分组更灵活。
- 这些端点是**元操作**，不经 eventBus（不需要 snapshot 广播）。注意：被删/归档项目若有 SSE 连接在线，前端那边自然失效（见 §B）。

### A.4 测试（`tests/server.test.js` / `tests/engine.test.js`，沿用 `startTestServer` / `createTempHarness`）
- archive → `GET /projects` 该项 `archived:true`；unarchive → 回到 false。
- delete → 项目目录消失、`GET /projects` 不再含它、`GET /:id/state` 走 ensureProject 会重建空白态（说明删除生效；测试断言删除后 summaries 不含该 id）。
- **越界保护**：`deleteProject` 不接受能逃出 `projects/` 的 id。
- **intake 续走回归**：start（无主题）→ phase intake + pending provide_research_direction；再 start（带 research_direction）→ phase contract_review、有 contract artifact。
- 沿用 M0/M1 全部测试保持全绿；CI 零模型额度。

### A.5 后端红线
- 删除/归档是元操作，**不污染研究状态机**（不 bump version、不改 phase_history）。
- `deleteProject` 限定在 `.researchclaw/projects/<id>` 目录内，防路径越界。
- engine 仍唯一状态源；`archived` 是 state 上的后端字段，先加 + 补测试。

## B. 前端（`researchclaw/web/src/`）

### B.1 范围
- 项目列表的**归档/恢复/彻底删除** UI（二次确认）+「已归档」分组视图。
- 面板 `ActionBar` 处理 `provide_research_direction` → 渲染输入框补录研究方向。
- （可选）面板左栏加「归档此项目」入口。

### B.2 数据层
- `api/types.ts`：`ProjectSummary` 加 `archived?: boolean`。
- `api/client.ts`：加 `archiveProject(id)` / `unarchiveProject(id)` / `deleteProject(id)`（均复用现有 `postJson`，命中 §A.3 端点）。

### B.3 intake 补录（核心修复）
- `lib/actions.ts`：`PanelAction` 加一种 `{ kind: "provide_direction"; label: string }`；`deriveActions` 把 `provide_research_direction` 映射成它（删掉「丢弃」的 default 分支注释）。补 `actions.test.ts` 用例。
- `components/ActionBar.tsx`：`provide_direction` 渲染一个输入框 +「提交研究方向」按钮；提交调 `startProject(projectId, direction)`（client 已有 `startProject`）。成功后**不本地拼 state**，等 SSE `snapshot`（与现有 approve/revise 一致，红线）。
- 效果：打开卡在 intake 的项目 → 看到输入框 → 填方向提交 → 引擎走到「契约待审」→ 正常推进。

### B.4 列表的归档/删除 UI（`routes/ProjectList.tsx`）
- 用 `summary.archived` 把列表分两组：**活跃项目**（默认显示）+ 可折叠的**「已归档（N）」**分组。
- 活跃项每条加「归档」按钮：**二次确认**（点一次变「确认归档?」，再点才发）→ `archiveProject` → `invalidateQueries(["projects"])`。
- 已归档项每条给「恢复」（`unarchiveProject`）+「彻底删除」（**二次确认**，醒目红色，`deleteProject`）。
- 二次确认用**内联两步**（非原生 `confirm`），便于测试与样式统一。
- 删除/归档当前正在面板查看的项目时：操作发生在列表页，天然无冲突；若从面板触发（§B.5），成功后 `navigate("/")`。

### B.5（可选）面板左栏入口
- `components/LeftColumn.tsx`：底部加「归档此项目」（二次确认）→ `archiveProject` → 成功 `navigate("/")`。彻底删除仍只放在列表的已归档视图，避免误删。

### B.6 前端测试
- `lib/actions.test.ts`：`provide_research_direction` → `provide_direction` 用例。
- 列表分组/二次确认的纯逻辑可抽小函数测（如 `splitProjects(summaries)`）。
- 沿用 vitest + typecheck 全绿。

### B.7 前端红线
- 不本地拼 state，归档/删除后靠 `invalidateQueries` 重拉列表；intake 补录靠 SSE snapshot。
- 删除是**彻底、不可恢复**，必须二次确认且文案明确；默认动作是**归档**而非删除。
- 不假装：归档只是隐藏，文件还在；UI 文案如实说明。
