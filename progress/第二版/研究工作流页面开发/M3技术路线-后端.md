# M3 技术路线（consult 一问一答）— 后端交接文档

本文档给**接手 M3 后端**的开发者。读完应能独立实现 consult 一问一答（headless `claude -p --resume`、多轮上下文、整轮存 raw_log、promote-to-artifact），而不需回头问架构。前端侧改动见同目录《M3技术路线-前端.md》。

前置：M0（引擎/gate/证据闭环）+ M1（实时通道 + 三栏面板）+ M2（`ClaudeCodeAdapter` workflow 模式、沙箱、成本护栏、降级、cli_chunk 实时流、异步化 begin/execute）已完成并测试通过（后端 `node --test` 109/109）。

> 关键复用：M2 已经把 spawn / stream-json 解析 / `cli_chunk` 推送 / 沙箱 / `CostTracker` / `EventBus` 回放缓冲 / 异步 begin+execute 这套全铺好了。M3 是在同一套地基上**加一种调用模式**，不是另起炉灶。

---

## 0. 一句话目标

```text
让人在面板点 Claude → 发一条消息 → headless `claude -p --resume <session_id>` 跑一轮 →
文本流式回面板 → 整轮存为 raw_log(consult)；多轮靠 --resume 续同一会话上下文；
consult 绝不推进 research state（不动 phase / phase_history / gate / 证据链）；
只有人显式 promote，才把某轮 consult 落成一个独立标记的 consult_note artifact
（进证据库、标注 adapter=claude+来源 consult，但不过 gate、不进 claim_evidence）。
默认 Haiku；Claude 不可用时 consult 诚实报「未接入」，不伪造 mock 回答。
```

对齐《第二版技术路线指南》§8 M3 验收 + §6.1 **V7（一问一答可用）**：面板点 Claude 发消息能拿到 Haiku 真实回复，整轮存为 consult raw_log，且不推进 state，可手动 promote。

## 1. 范围

### 1.1 M3 必须做（后端）
- `ClaudeCodeAdapter.consult(request)`：**consult 模式**——free-form（无 forced schema、不读 out.json）、`--resume` 续会话、捕获 `session_id`、逐轮文本经 `cli_chunk`（标 `kind:"consult"`）实时推面板，返回 `{ ok, session_id, text, usage, raw }`。
- consult 会话管理：**每项目单一会话线**（§4）。`session_id` 持久化到 `state.consult`（纯会话元数据，非结论），`--resume` 续上下文。
- 整轮落 `raw_log`（标 `consult`），ref 进 `state.current.raw_log_artifact_refs`（复用 M2 的 `landCliRawLog` 思路，扩展 content）。
- `promote-to-artifact`：人指定某轮 consult raw_log → 生成 `consult_note` artifact（新类型，§6），进证据库但**不过 gate、不推进 phase、不进 claim_evidence_map**。
- 端点（§7）：`POST /projects/:id/consult`（异步：秒回 ack + 后台跑 + `cli_chunk`/`consult_message` 实时）、`POST /projects/:id/consult/promote`。
- 成本与安全护栏沿用 M2（默认 Haiku、沙箱、受限 allowedTools、超时、token/会话预算、redactSecrets）；consult 用量也计进 `CostTracker`（`by_phase` 桶 `consult`）。
- 不可用降级：Claude 不接入 / 无二进制 / over budget → consult **诚实拒绝**（返回 honest error），**不回退 mock**（consult 没有要续命的 pipeline，假回答会破红线）。

### 1.2 M3 明确不做（留 M4 / v3+）
- **运行指标面板 + 成本告警 UI** → M4（后端 M3 只把 consult 用量算进 `state.usage`）。
- **cache token 计价细化** → M4（M3 沿用 M2 的 input/output 估算）。
- **OpenClaw hook 异步联调** → M4。
- consult 多会话线 / 切话题 thread；consult 选模型下拉（M3 钉死 Haiku）；Gemini / Codex consult（维持占位）。
- promote 选目标 schema / 过 gate（本版 promote 只落独立标记 artifact）。

## 2. 架构变化与新增模块

```text
ResearchOrchestrator（唯一状态源，不变）
  ├─ this.adapter.run(request)        ← workflow 模式（M2，不变）
  └─ consult 路径（M3 新增）
       beginConsult(projectId, message)      → 秒回 ack（不动 research 状态机）
       executeConsult(projectId, message)    → 后台：
            this.adapter.consult({ project_id, message, session_id })   ← 新增 adapter 方法
              ├─ sandbox.create()                  ← 复用 M2 沙箱
              ├─ spawn claude -p <message> --resume <session_id?> (stream-json, free-form)
              │    └─ 每个 assistant 文本块 → eventBus.emit(cli_chunk, {kind:"consult", text})
              ├─ 捕获 session_id（init/result 事件）
              └─ 返回 { ok, session_id, text, usage, raw }
            → landConsultRawLog(state, raw, message, sessionId)   ← 落 raw_log(consult)
            → state.consult.session_id = sessionId                ← 会话元数据（非结论）
            → costTracker.record(usage, phase:"consult")
            → emit consult_message + snapshot
       promoteConsult(projectId, rawLogRef)
            → createArtifact(type:"consult_note", adapter:"claude", ...)
            → state.current.consult_note_refs.push(ref)           ← 不过 gate / 不推进 phase
            → emit snapshot
```

新增 / 改动文件：
- `adapters/claudeCode.js` — 加 `consult(request)`（与 `run` 并列，共享 spawn/解析/沙箱底层）。
- `engine/orchestrator.js` — 加 `beginConsult` / `executeConsult` / `promoteConsult` / `landConsultRawLog`；新增 `consultInflight` Map（按项目串行化多轮）。
- `evidence/types.js` — `artifactTypes` 集合加 `consult_note`。
- `server.js` — 加 `/consult`、`/consult/promote` 端点。
- `adapters/claudeConfig.js` — `resolveClaudeModel()` 复用，不改（consult 同样默认 Haiku）。

不动：workflow 模式 `run`、所有 gate、`workflows/*`、`ModelAdapter.run` 签名、research 状态机主体。

## 3. consult 模式 vs workflow 模式（一张表讲清差异）

| 维度 | workflow 模式（M2，`run`） | consult 模式（M3，`consult`） |
| --- | --- | --- |
| 触发者 | engine（phase 执行器） | 人（面板点 Claude 发消息） |
| 输出形态 | 结构化 `out.json`，过 schema + gate | free-form 文本，不强制 schema |
| 结论性 | ✅ 唯一可信结论（artifact） | ❌ 过程流；promote 后也只是「采纳笔记」，非 gate 结论 |
| 落档 | `contract` 等结构化 artifact + `raw_log` | `raw_log(consult)`；promote 才加 `consult_note` |
| 推进 state | 是（phase / gate / phase_history） | **否**（红线）；只写 `state.consult` 会话元数据 |
| 上下文 | 单次（每 phase 独立 prompt） | 多轮（`--resume <session_id>`） |
| 降级 | 失败 → 回退 mock（保 pipeline） | 不可用 → 诚实拒绝，**不回退 mock** |
| allowedTools | `Read,Write,WebSearch`（要写 out.json） | 受限只读（§9，默认不放 Write/Bash） |
| 模型 | Haiku（钉死） | Haiku（钉死，本版不可选） |

> **红线核心**：consult 的任何文本，无论 promote 与否，都**不进 `claimEvidenceGate` / 不进 success summary / 不算 phase pass**。promote 出来的 `consult_note` 是「人工采纳、可溯源、明确标注未过 gate」的旁路证据，不是流程结论。

## 4. consult 会话模型（每项目单一会话线）

- 一个 `projectId` 维护**一个** Claude consult 会话。首轮 `claude -p <msg>`（无 `--resume`）→ 从 stream-json 的 `system`(init) 或 `result` 事件捕获 `session_id` → 存 `state.consult.session_id`。后续轮 `claude -p <msg> --resume <session_id>` 续上下文。
- `state.consult` 形状（**纯会话元数据，引擎写，但绝不参与 phase/gate/证据**）：
  ```js
  state.consult = {
    session_id: "sess_xxx" | null,
    turn_count: 3,
    last_turn_at: "2026-06-08T...",
    raw_log_refs: ["artifacts/.../<id>.json", ...]   // 每轮 consult raw_log，按序
  }
  ```
- **为什么持久化 session_id 到 state.json**：进程重启后 `--resume` 仍能续上同一 CLI 会话；durable 记录还是 raw_log artifacts。这不算「推进 state」——它不碰 `state.phase` / `state.current` 的研究 ref / `phase_history`。文档与代码注释都要写清这条边界，避免后人误以为 consult 改了状态机。
- 多轮串行：同一项目同时连发两条消息会破坏 `--resume` 顺序 → `consultInflight` Map 按 `projectId` 串行（前一轮没结束，新消息排队或拒绝；建议**排队**，保证顺序）。

> 兜底：若某轮没拿到 `session_id`（CLI 形态变化 / 异常），降级为「无 resume 的独立轮」并在 raw_log 标注 `resumed:false`，不崩。

## 5. `ClaudeCodeAdapter.consult(request)` 设计

### 5.1 CLI 调用
```bash
claude -p "<人输入的 message>" \
  --model claude-haiku-4-5 \
  --output-format stream-json --verbose \
  --allowedTools "Read,WebSearch" \
  --max-turns 8 \
  [--resume <session_id>]            # 有会话时续上下文
  # cwd = 复用 M2 沙箱目录（隔离 + 清理）
```
- 不附 schema 尾句、不要求写 out.json（free-form）。
- `--max-turns` 给小值（建议 ≤ 8）：consult 是对话不是长任务。超时沿用 M2 定时器 kill。

### 5.2 stream-json 解析（复用 M2 `consume` 底层，拆出共用部分）
- 逐行解析；`assistant` 文本块 → `emitChunk(request, { kind:"consult", role:"对话", text, ts })` 实时推面板；累计成 `text`（整轮回答）。
- 捕获 `session_id`：M2 `consume` 现在只取 `model`/`usage`/`turns`/`duration_ms`；M3 扩展为也取 `event.session_id`（init 与 result 事件通常都带）。
- `usage`：沿用 M2（input/output tokens + model + turns + duration_ms）。
- 容错：单行解析失败跳过；stderr 收集进错误。

> **建议重构**：把 M2 `consume` 里「逐行读 + 解析 + 提取 usage/session/model」抽成一个可被 `run` 和 `consult` 共享的内部方法，差异只在「`run` 末尾读 out.json+校验」vs「`consult` 末尾返回纯文本」。避免两份解析逻辑漂移。

### 5.3 返回形状
```js
// 成功
{ ok: true, adapter: "claude", session_id: "sess_xxx", text: "<整轮回答>",
  usage: { input_tokens, output_tokens, model, turns, duration_ms },
  raw: { transcript: "<整段 stream-json>", summary: { model, time, role:"对话", summary:<text 前 280>, artifact_refs: [] } } }

// 失败（honest，不回退 mock）
{ ok: false, adapter: "claude", error: { code, message, retryable } }
// code: "unavailable" | "timeout" | "over_budget" | "spawn_error" | "empty_reply"
```

## 6. promote-to-artifact 与 `consult_note` 类型

- 新 artifact 类型 `consult_note`：在 `evidence/types.js` 的 `artifactTypes` 集合加一项即可（store 不二次校验 type，`createArtifact` 是唯一校验点）。
- `promoteConsult(projectId, rawLogRef, note?)`：
  1. 读该 consult `raw_log` artifact（必须是本项目、type=raw_log 且 workflow=consult，否则拒绝）。
  2. `createArtifact({ type:"consult_note", phase: state.phase, workflow:"consult_promote", adapter:"claude", inputRefs:[rawLogRef], evidenceRefs:[rawLogRef], content: { source_raw_log_ref: rawLogRef, question, answer_text, transcript_ref, note: note||null, promoted_at } })`。
  3. `appendArtifact` → `state.current.consult_note_refs = [...(...||[]), ref]`。
  4. **不** `recordPhase`、**不**改 `state.phase`、**不**进 `artifactTypeByStateKey`（所以 `availableArtifacts` / `claimEvidenceGate` 天然不会把它当证据命中）。
  5. `finishManual` 写 state + emit snapshot。
- 幂等/防重：同一 rawLogRef 重复 promote 应去重（已 promote 过则返回已有 ref，不重复落档）。

> **红线落地**：`consult_note` 进证据库只为「可溯源 + 诚实标注人工采纳了哪轮对话」，它**不**满足任何 claim 的 `required_evidence`。M4 前端要把它和 gate 过的 artifact 在视觉上分开（前端文档 §3.5）。

## 7. 端点（server.js）

| 方法/路径 | body | 行为 | 返回 |
| --- | --- | --- | --- |
| `POST /projects/:id/consult` | `{ message }` | 异步：`beginConsult` 秒回运行态 ack，后台 `executeConsult` 跑一轮 + `cli_chunk(kind:consult)` 实时 + 结束落 raw_log + emit `consult_message`/snapshot | `{ ok, running:true }` 或 honest `{ ok:false, error }`（Claude 不可用） |
| `POST /projects/:id/consult/promote` | `{ raw_log_ref, note? }` | `promoteConsult` 同步落 `consult_note` | `{ ok, artifact_ref }` |

- consult 端点沿用 M2 的「秒回 ack + 后台执行 + SSE 实时」范式（参考 `/start` → `beginDraftFromText` + `executeContractRun`）。
- SSE 端点（已有）只新增转发 `consult_message` 事件类型，端点逻辑不变。`cli_chunk` 已被 M2 回放缓冲覆盖；consult 轮开始时**建议 `clearCliChunks` 仅清自己用的临时区**——或给 consult 单独一类事件不进 workflow 的 `cli_chunk` 缓冲（避免污染 workflow 过程流回放）。简洁做法：consult 的实时文本走 `cli_chunk` 但带 `kind:"consult"`，前端按 kind 分流；回放缓冲对两类都存无妨（前端分流）。

## 13. 红线（务必遵守）

1. **consult 不推进 state**：不动 `phase` / `phase_history` / gate / `claim_evidence`；`state.consult` 仅会话元数据。
2. **两通道物理分离**：consult 文本永远是过程流；`consult_note` 是人工采纳笔记、明确标注未过 gate，**不**满足任何 claim 证据。
3. **engine 边界不破**：adapter 不写 research state；`ModelAdapter.run` 签名不变；consult 是 adapter 新增方法，state 只在 orchestrator 写。
4. **默认 Haiku，绝不默认 Opus**；consult 本版不开放选模型。
5. **不可用要诚实**：Claude 没接 / 超预算 → consult **拒绝**，绝不用 mock 伪造一段对话（与 workflow 降级不同：consult 没有 pipeline 要续命，假答直接破红线）。
6. **沙箱 + 受限 allowedTools（不放 Write/Bash）+ redactSecrets**，transcript 落档脱敏。
