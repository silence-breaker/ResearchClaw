# M2 技术路线（ClaudeCodeAdapter workflow 模式）— 前端交接文档

本文档给**接手 M2 前端**的开发者。M2 的重心在后端（见同目录《M2技术路线-后端.md》）；前端只做**把后端 M2 新产生的真实数据诚实地显示出来**这一件事，不抢跑、不造假。

前置：M1.0–M1.4 已完成（三栏面板 / 证据映射 / artifact 详情抽屉 / SSE 实时刷新），web vitest 69/69、typecheck 绿。

---

## 0. 一句话目标

```text
当后端某个 phase（M2 = contract_draft）由真实 Claude Code 跑出来时，
面板要：①右栏过程流显示真实 CLI transcript（不再是占位）；
②每个 artifact 诚实标注是 claude 还是 mock 产出；
③CLI 运行过程经 SSE cli_chunk 实时滚动；④降级 mock 时如实提示。
不做完整成本指标面板 / 告警（那是 M4），只把 usage 轻量透出。
```

---

## 1. 范围

### 1.1 M2 前端必须做
- 右栏 `ProcessFeed`：从「只列 raw_log ref」升级为**真实 CLI 过程流**——每条结构化摘要 `{ model, time, role, summary, artifact_refs }`，点击进 artifact 抽屉看完整 transcript。
- **来源徽章**：artifact 列表 / 详情抽屉 / 当前阶段卡片显示 `producer.adapter`（`claude` 实色 / `mock` 灰显），让「两通道」在视觉上可分辨。
- **cli_chunk 实时流**：`useProjectStream` 扩展为可处理非 snapshot 事件；右栏过程流随 `cli_chunk` 逐条滚动（CLI 正在干什么）。
- **降级提示**：某 phase 被降级 mock（无 key / 超限 / 失败）时，面板显诚实 banner / 标记「Claude 不可用，已降级 mock」。
- **轻量 usage 透出**：`MetricsRow` 的「本会话成本」从「—」改为读 `state.usage`（token / 估算成本）；接近上限不做花哨告警（留 M4），先把真实数字显出来。

### 1.2 M2 前端明确不做（留 M3/M4）
- **consult 一问一答输入框**仍 `disabled` 占位（真实对话是 M3）。右栏模型按钮不做「点击发消息」。
- **完整运行指标面板 + 成本告警 / 阈值高亮 / 趋势**：M4。M2 只透出原始数字。
- Gemini / Codex：维持占位。

## 2. 依赖的后端新数据 / 事件（M2 后端提供）

| 来源 | 形状 | 用途 |
| --- | --- | --- |
| `artifact.producer.adapter` | `"claude" \| "mock" \| "manual"`（**已存在于类型**，M2 起真实出现 claude） | 来源徽章 |
| `raw_log` artifact content（扩展） | `{ model, time, role, summary, artifact_refs, transcript_ref? }` | 过程流摘要项 + 点开看 transcript |
| SSE `cli_chunk` 事件（新增） | `{ phase, role, text?, tool?, ts }` | 右栏实时滚动 |
| `state.usage`（后端新增字段，随 snapshot 来） | `{ input_tokens, output_tokens, est_cost_usd, cli_calls, cli_failures }` | 轻量成本透出 |
| 降级标记 | 后端在降级时通过事件/字段透出（与后端 §7 对齐：产物 `adapter:"mock"` + 一条提示事件） | 降级 banner |

> **不要在前端伪造任何上述字段**。后端没给就显「—」或不显；前端只调 HTTP/SSE，不本地拼 state（红线，与 M1 一致）。

## 3. 逐组件改动（`researchclaw/web/src/`）

### 3.1 `api/types.ts`
- 给 `ProjectState` 加可选 `usage?: { input_tokens; output_tokens; est_cost_usd; cli_calls; cli_failures }`（镜像后端，不新造业务字段）。
- `raw_log` content 是 `unknown`，渲染时按上面摘要形状窄化（防御式读取，缺字段降级显示）。

### 3.2 `api/useProjectStream.ts`（扩展，不重写）
- 现状只处理 `snapshot`。新增：监听 `cli_chunk` 事件 → 推入一个**有上限的本地环形缓冲**（如最近 100 条），供右栏消费。
- `snapshot` 仍是真相源（usage / artifact / 来源都在里面）；`cli_chunk` 只驱动过程流动画，**不更新结论性视图**。
- 断线兜底逻辑不变（5s 轮询 `/state`）。

### 3.3 右栏 `RightColumn.tsx` / 新 `ProcessFeed`
- 把现有「过程流（raw_log）」从纯 ref 列表，升级为摘要卡片列表：`模型名 · 时间 · 角色标签（规划/文献/复现…）· 摘要 · 挂载产物`；点击 → 既有 `ArtifactDetailDrawer` 看完整 transcript（复用 M1.4 的抽屉 + `RefChip`）。
- 顶部叠加 `cli_chunk` 实时区：当前 phase 正在跑时，逐条滚动 CLI 动作（淡色、可折叠），**明确标注是过程透明度、非结论**。
- 模型按钮：`Claude` 在 workflow 模式下可显「运行中 / 空闲」状态指示（只读），**consult 输入框仍 disabled**（M3）。

### 3.4 来源徽章（复用，不新造组件）
- 新增极小 `AdapterBadge`（`claude` = accent 实色，`mock` = 灰，`manual` = 更淡）。
- 用在：右栏 artifact 列表、`ArtifactDetailDrawer` 头部、`CurrentPhaseCard`/阶段状态 tab 的 ref 旁。
- 语义：让人一眼看出「这条结论是真实 CLI 跑的还是 mock 回放的」——服务于两通道红线。

### 3.5 降级 banner
- 当后端透出降级（产物 `adapter:"mock"` 且发生在本应 Claude 的 phase，或收到降级事件）→ 中栏/右栏顶部一条琥珀提示：「Claude 当前不可用（无 key / 超限 / 失败），已自动降级 mock，产物来源已标注」。诚实、不报错式吓人。

### 3.6 `MetricsRow.tsx`（轻量）
- 「本会话成本」：`state.usage` 存在则显 `est_cost_usd`（+ tooltip 拆 token）；否则维持「—」。
- 可加「CLI 调用 / 失败」次数（来自 `usage.cli_calls / cli_failures`）。
- **不做**阈值高亮 / 告警弹层（M4）。

## 4. 两通道红线在 UI 的落地（最重要）

| 通道 | UI 位置 | 能否当结论 |
| --- | --- | --- |
| transcript / cli_chunk / raw_log 摘要 | 右栏过程流 | ❌ 仅过程透明度，永远标「过程」 |
| 结构化 artifact（过 gate） | 中栏契约 / 证据映射 / 阶段状态 + 抽屉 | ✅ 唯一可信结论，可点 ref 溯源 |

- 右栏任何文本**不得**被当作中栏结论引用；证据映射仍只来自 `claimEvidenceGate`（M1.4 已落地）。
- 来源徽章是为了**诚实**，不是为了把 mock 包装成 claude。降级就显降级。

## 5. 内部里程碑（建议顺序，跟随后端）

| 步 | 交付 | 依赖后端 | 验收 |
| --- | --- | --- | --- |
| F2.0 | `useProjectStream` 处理 `cli_chunk` + 环形缓冲；类型补 `usage` | 后端 cli_chunk 事件（M2.3） | 单测：事件归类、缓冲上限 |
| F2.1 | `AdapterBadge` + 右栏 ProcessFeed 摘要卡片 + 抽屉看 transcript | 后端 raw_log 扩展（M2.2/2.3） | 本地手验：claude 产物显实色徽章，可看 transcript |
| F2.2 | cli_chunk 实时滚动区 + 降级 banner | 后端事件 | 真跑一次 contract_draft，右栏实时滚动；拔 key 看降级提示 |
| F2.3 | MetricsRow 轻量 usage 透出 | `state.usage`（M2.2） | 真跑后成本/调用数有真实值 |

> 后端未就绪前，F2.0/F2.1 可先用**录制的 raw_log fixture / 假 cli_chunk 事件**驱动 UI 开发（mock 数据明确标注），但**上线前必须接真后端数据**，不留写死。

## 6. 测试

- `useProjectStream` 事件分流（snapshot vs cli_chunk）与缓冲上限：vitest 纯逻辑测。
- `AdapterBadge` / ProcessFeed 摘要项的防御式读取（缺字段不崩）：组件/纯函数测。
- usage 透出与缺失降级显「—」。
- 沿用 M1 全部 vitest + typecheck 保持全绿。

## 7. 红线（与 M1 一致 + M2 强调）

1. **结论只来自 artifact**；右栏过程流永远是「过程」，不可当结论。
2. **不让前端跑在后端能力前**：consult 输入框 M2 仍 disabled（M3）；完整指标面板 / 告警留 M4。
3. **不改数据契约迁就 UI**：`usage` 等字段先在后端加并补测试，前端只镜像。
4. **降级要诚实**：来源徽章如实显示 claude / mock；降级有提示，不假装已接入。
5. **mock 永远能跑**：后端未开 CLI 时面板照常工作（全 mock 来源徽章为 mock），不报错。
